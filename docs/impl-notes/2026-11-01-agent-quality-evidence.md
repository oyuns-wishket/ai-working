# Agent quality and recovery evidence

## Goal and authorization
The user requested iterative improvement of a persistent development agent, with terminal-like performance, nondeveloper maintenance and a team-defined quality rubric. The existing authorization includes updating the reusable bot development skill. Customer-specific implementation stays in its private repository.

## Change and rationale
Extended the existing development-mode reference with semantic retrieval before LIMIT, durable explicit constraints, exact delivery receipts and external at-least-once limits. Added pre-turn failure handling, bounded initialization/cancellation, recovery-only operator authority, failure-inclusive metrics, streaming and snapshot-consistent backups, admission with unknown usage, and evidence-based plan versus product evaluation.

The investigation-mode boundary remains unchanged. We rejected a new duplicate skill, universal full-access mode and awarding product performance scores from unit tests. A report evaluator does not collect a live benchmark; employee training evidence cannot be simulated by agents.

## Validation
Passed: skill validation (25 skills), public contents/full-history audit, hook tests (82), bootstrap Python tests (96), bot runtime-guard tests (11), bootstrap status (78 healthy links/settings). Bootstrap applied successfully. A separate reviewer checked the generalized guidance against realistic recovery, stale receipt, unsupported capability and deferred chat scenarios. Remote public-safety must pass after publication; its run is the publication evidence.

## Deviations and follow-up
No new entrypoint or personal/customer values. Implementation-specific thresholds remain project policy. Real paired trials and human usability checks are required in the consuming project before claiming product readiness.
