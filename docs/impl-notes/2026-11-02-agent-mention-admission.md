# Invited-channel mention admission

## Goal and decisions
A development bot may be authorized for any invited internal workspace channel and any participating employee. Static channel/user lists are an implementation option, not a universal prerequisite. Preserve the user's established policy rather than repeatedly requesting trial identifiers.

## Gate evidence
The user explicitly requested invitation plus mention use without fixed participant/channel registration, and previously requested that reusable bot-development lessons be maintained in this skill. Existing publication authorization applies. This public change contains no customer identifiers or deployment metadata.

## Changes and reasoning
Document policy choice, authenticated enrollment, shared execution/delivery authorization, mention-start conversation continuity, Slack Connect uncertainty and actual connection evidence. Reject a wildcard runtime actor policy: transport identity must not silently grant operator authority or private task access. Ordinary channel chatter does not become a development task merely because the bot can receive it.
