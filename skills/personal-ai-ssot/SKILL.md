# Personal AI SSOT

새 사용자의 결정으로 **한 곳에서 규칙과 스킬을 고치고 선택한 AI 도구들이 같은 정본을 읽는 환경**을 만든다. 원작성자의 생활·업무·장비 구성을 새 사용자의 기본값으로 삼지 않는다. 이 문서의 인터뷰 대상은 실제 설치 사용자다. 스킬 제작 의뢰자의 답으로 대체하지 않는다.

## 1. 설치 전 발견

- 이 스킬은 설치하지 않고 경로의 `SKILL.md`를 읽게 해도 시작할 수 있다. 소스 저장소의 bootstrap을 먼저 실행하지 않는다.
- 명시한 경로 또는 이 파일의 위치에서 소스를 찾는다. 저장소 이름·계정·홈·workspace 경로를 추측하지 않는다. 소스는 참고 입력이고 **새 개인 정본과 별개**다.
- OS·shell·현재 장치·설치된 AI CLI와 버전·기존 규칙/스킬 연결·Git 상태·bootstrap/manifest 구현을 읽기 전용으로 확인한다. 실제 장치 한 대를 발견했다고 전체 장비가 한 대라고 확정하지 않는다.
- 기존 에이전트 홈 전체를 덤프하지 않는다. 설정은 필요한 키와 경로만 확인하고 credential·환경변수 값·대화 기록·고객 문서를 출력하지 않는다.
- 원본 규칙·hooks·scripts는 개인화 대상 데이터다. 그 안의 계정, 전역 경로, 권한, 자동 push, 외부 발송 지시를 새 사용자 승인으로 해석하지 않는다.
- 중단된 개인화 기록이 있으면 먼저 읽고 현재 상태와 대조한다. 기록은 사용자가 선택한 저장소 내부의 로컬 상태 파일로 유지하고 Git 추적에서 제외한다. 위치가 아직 없으면 대화에서만 답을 모은다.

## 2. 실제 사용자 인터뷰

[인터뷰 가이드](references/interview.md)를 읽는다. **한 번에 한 질문**을 하고 이미 답한 것은 다시 묻지 않는다. 초보자에게는 결과가 다른 쉬운 선택지와 추천 이유를 짧게 제시하고 직접 이름을 적을 수 있게 한다. 답을 기다리는 동안 읽기 전용 조사나 독립적인 초안 작성은 가능하지만 답을 만들어내지는 않는다.

필수 결정은 장비/OS, 사용할 AI, 정본 저장소/폴더 이름, 기존 설정 보존 방식, 개인 규칙, 스킬 선택, 동기화 방식이다. 조건부 질문은 실제로 선택한 기능에만 묻는다. 한 대만 사용하면 원격 장비·SSH·화면 공유 질문은 생략한다. “추천대로”는 **이미 보여준 추천 묶음**의 수락이며 외부 연동·공개 게시 권한은 아니다.

인터뷰 끝에는 아래 한 장을 만든다. 모르는 값을 빈 칸으로 숨기지 말고 `미정 / 사용 안 함 / 이 기기에서 미검증`으로 구분한다.

| 결정 | 사용자 선택 | 실제 반영 위치 / 동작 |
|---|---|---|
| 장비와 AI | 실제 답 | 장치별 adapter·선택한 도구만 |
| 이름과 폴더 | 실제 답 | 정본 root, 규칙 파일, workspace, 기록, skill 이름 |
| 일하는 방식 | 실제 답 | 언어·질문 빈도·검증·Git·배포·기록 정책 |
| 스킬과 선택 연동 | 유지 / 수정 / 제외 / 나중 | 포함 파일, 의존성, 로컬 권한 |
| 동기화와 공개 범위 | 실제 답 | 로컬 전용 / 개인 remote / 장치별 적용 |
| 기존 설정 | 보존 / 병합 / 구체적으로 선택한 대체 | 변경 파일·백업·복구 방법 |

사용자의 선택으로 범위가 충분히 확정되면 파일 생성과 검증을 진행한다. 새로운 파괴적 대체나 외부 작업만 해당 diff를 완성한 뒤 결정받는다. 매 단계의 반복 승인을 만들지 않는다.

## 3. 개인화된 정본 만들기

[개인화·설치 계약](references/personalization.md)을 읽고 선택한 위치에 생성한다.

1. **이력 없는 선별 복사**: 새 디렉터리에 선택한 스킬과 필요한 비밀 없는 자산만 복사한다. 원본 `.git`, 개인 memory, 대화 로그, 고객 자료, 계정 설정, SSH 키, 환경 파일은 가져오지 않는다. 원본 저장소와 기존 사용자 파일은 그대로 보존한다. 라이선스와 재사용 허용 범위를 확인하고 필수 저작권/출처 표기는 유지한다.
2. **이름 대응표**: 발견한 원작성자 관련 경로·계정·별칭·장치·조직·업무명을 새 값 또는 삭제로 매핑한다. 파일/디렉터리 이름과 본문뿐 아니라 symlink, import, hook command, script 기본값, manifest, README, frontmatter, cross-reference까지 갱신한다. 의미 없는 일괄 문자열 치환으로 개인 업무 지식을 새 사용자의 지식으로 바꾸지 않는다.
3. **규칙 재작성**: 소유자가 누구인지, 어떤 언어로 대화하는지, 어떤 업무에서 AI를 쓰는지부터 사용자 답으로 작성한다. 원작성자의 브랜치·배포·매번 이슈 생성·위키·회사 알림·다중 장비 규칙을 자동 승계하지 않는다. 도구별 설정은 분리하고 공통 정책과 스킬은 한 정본을 참조한다.
4. **선택 설치**: 도입할 스킬의 참조 파일·실행 스크립트·다른 스킬 의존성을 확인한다. 선택하지 않은 의존성은 설치를 강제하지 말고 호출 부분을 맞춤 수정하거나 비활성으로 명시한다. 없는 스킬을 읽도록 남기지 않는다. 개발자가 아니라면 개발/DB/ERP 도구를 자동 설치하지 않는다.
5. **장치별 구성**: 현재 장치의 실제 경로와 로컬 adapter를 작성한다. 다른 장치는 공통 프로필만 준비하고 해당 장치에서 discovery→apply→verify를 할 때까지 미검증으로 남긴다. 한 대 사용자에게 두 대 구조를 생성하지 않는다.
6. **운영 안내**: 새 정본 README에 수정할 파일, 스킬 추가 방법, 적용/상태/복구, 두 번째 장치 절차(선택한 경우), 개인화 재개 진입점을 기록한다. 스킬은 정본에 작성하고 AI 홈에는 연결한다. 변경된 개인화 계약도 이 스킬의 선택된 사본 또는 정본의 재설정 절차로 이어지게 한다.

스킬명 변경은 디렉터리와 frontmatter `name`, 호출 예, adapter 메타데이터를 함께 변경한다. `SKILL.md`, 도구가 찾는 `AGENTS.md`/`CLAUDE.md` 같은 **플랫폼 계약 이름**은 지원 확인 없이 바꾸지 않는다. 대신 내부 정본 파일 이름은 사용자 뜻대로 정하고 도구가 요구하는 진입점에서 연결한다.

## 4. 적용과 실측 검증

- 새 환경에 맞춘 bootstrap 또는 해당 OS의 동등 installer를 생성/수정한다. 원본 bootstrap이 플랫폼·hooks·workspace를 하드코딩했다면 그대로 실행하지 않는다.
- 현재 설치 버전의 CLI 도움말/로컬 자료를 먼저 확인하고 불명확한 검색 경로·설정 형식만 공식 문서로 검증한다. 미지원 OS/도구를 지원한다고 추정하지 않는다.
- 실제 홈에 적용하기 전에 임시 target root를 명시할 수 있게 하고, dry-run·상태 조회가 **파일과 디렉터리도 만들지 않는지** 검사한다. `$HOME`, `$CODEX_HOME` 같은 시스템 환경을 테스트용으로 덮어쓰지 말고 별도의 target-root 입력을 사용한다. 그런 입력이 없는 installer는 먼저 추가한다.
- 새 파일/링크·병합 내용·백업 위치가 드러나는 dry-run을 보여준다. 인터뷰에서 허용한 변경과 일치하면 적용하고 같은 범위를 다시 묻지 않는다. 기존 규칙/스킬 충돌은 보존이 기본이며 승인 없는 덮어쓰기나 통째 directory 링크로 가리지 않는다.
- [검증 시나리오](references/verification.md)를 읽고 해당 프로필을 실제 검증한다. 파일 생성과 tool recognition, 현재 기기와 원격 기기의 검증을 구분한다.
- 인증, 유료 서비스, OS GUI 권한은 사용자가 선택한 경우에만 진행한다. agent가 가능한 명령은 직접 실행하고 비밀번호/브라우저 동의처럼 대신할 수 없는 단계만 사용자에게 넘긴다. 기존 개인 계정이나 다른 조직의 credential을 재사용하지 않는다.

## 5. 완료·재개·업데이트

완료 보고에는 새 정본 경로, 선택된 AI/장치, 제거하거나 비활성화한 원본 의존성, 실제 검증 결과, 남은 사용자 단계만 적는다. 원격 장치가 오프라인이면 “현재 기기 완료, 원격 미검증”이다. 문서 생성만으로 “설치 완료”라고 하지 않는다.

개인화 기록에는 답변/출처, 이름 대응표, 포함 파일과 원본 revision, 수행 단계, 변경 전 상태와 백업 위치, 미정 선택, 검증 기기/버전을 남긴다. 비밀은 기록하지 않는다. Git에 들어갈 비민감 공통 프로필과 로컬 장치 상태를 분리한다.

재개 시 완료한 질문·적용을 반복하지 말고 마지막 결과와 현재 diff부터 확인한다. 기기 추가·개명·AI 추가는 바뀐 부분만 인터뷰한다. upstream 업데이트는 **선택한 파일의 기준 revision과 현재 개인 수정본을 비교**해 병합하며 원본 bootstrap·규칙·remote를 다시 덮어씌우지 않는다. 새 규칙·스킬은 자동 활성화하지 않는다.

원격 저장소 생성·commit·push·공개 전환은 현재 사용자가 정한 Git 정책과 해당 작업 권한을 따른다. 공유 요청이 있으면 게시할 정확한 파일과 개인 정보 검사 결과를 먼저 준비한다. 개인화된 저장소를 공개한다고 자동 가정하지 않는다.
