# 개인화와 설치 계약

## 파일 구조와 상태

고정된 회사 폴더 구조를 강요하지 않는다. 사용자가 선택한 명명 아래 다음 역할만 확보한다.

| 역할 | 내용 | 저장 범위 |
|---|---|---|
| 공통 정책 정본 | 사용자 답으로 작성한 작업 규칙 Markdown | 개인 저장소 |
| 스킬 정본 | 선택한 `<skill>/SKILL.md`와 필요한 자산 | 개인 저장소 |
| 비민감 프로필 | 선택 도구·업무 정책·포함 스킬·논리적 경로 | 개인 저장소, 공개 여부는 별도 |
| 장치 설정 | OS, 실제 정본/프로젝트 경로, adapter target | machine-local, Git 제외 |
| 진행/복구 기록 | 실제 답·이름 매핑·적용 상태·백업 목록 | machine-local, Git 제외 |
| 설치 진입점 | explicit target-root, dry-run, apply, status, rollback | 개인 저장소 |
| 사용 안내 | 수정·스킬 추가·재개·업데이트 방법 | 개인 저장소 |

경로는 실행 위치에서 정본 root를 구하고 나머지는 상대 경로/장치 설정에서 해석한다. 경로에 공백·한글이 있어도 동작하게 인자를 전달하며 쉘 문자열 삽입으로 실행하지 않는다. 이름에 경로 traversal·절대경로를 허용할 위치와 단순 slug 위치를 구분한다.

장치별 실제 경로가 달라도 공통 정책은 같아야 한다. 다른 장치에서 쓰는 symlink의 절대 target을 Git에 복제하지 않는다. 해당 장치에서 adapter를 다시 생성한다. 원격 접속 없이 Git만으로 두 기기 동기화를 선택할 수도 있다.

## 원작성자 흔적 제거

선별 복사 전 소스의 파일명 목록과 bootstrap/manifest/README를 읽어 원작성자 식별자를 수집한다. 개인 memory·고객 자료의 본문을 탐색 대상으로 확장할 필요는 없다. 생성물에는 다음을 검사한다.

- 사람·회사·계정·이메일·저장소 owner·봇 이름·장치 별칭.
- 개인 홈 경로·프로젝트 폴더·SSH host·IP·도메인·port·launch agent label.
- 업무 도메인 가정·근태 대상·채널/프로젝트/워크스페이스 ID·자동 발송·private wiki/marketplace 의존성.
- symlink와 import의 target, hook command, script의 default, metadata와 frontmatter, 문서 링크.
- 제외한 스킬을 호출하는 정책·workflow와 없는 자산.

검색은 `rg --files --hidden`과 고정 문자열 검색을 사용하되 Git 내부·비밀 파일은 제외한다. 결과는 파일 경로와 분류 위주로 보고하고 secret을 그대로 출력하지 않는다. 문자열 검사는 의미 검토를 대체하지 않는다. 작성자 이름이 없어도 “매일 회사 근태 알림” 같은 정책은 새 사용자의 답 없이는 제외한다.

이름 대응표에서 파일 개명은 참조부터 조사한 뒤 수행한다. 동일한 새 이름으로 충돌하면 기존 파일을 보존하고 해결한다. 플랫폼 필수 이름이나 라이선스까지 바꾸지 않는다. 필수 법적 표기 및 사용자가 선택한 일반 외부 서비스 URL은 허용 항목에 사유를 남기고 실행 경로의 원작성자 연결과 구분한다.

새 저장소는 원본의 `.git`/remote/history 없이 만든다. 이미 fork/clone한 경로를 자기 정본으로 쓰고 싶어 하면 그 이력의 개인 정보까지 이름 치환으로 사라지는 것은 아님을 설명하고 깨끗한 별도 정본을 추천한다. 기존 `.git` 삭제나 history rewrite는 자동 수행하지 않는다. 라이선스/재배포 권한이 불명확한 파일은 재배포를 보류하고 독립적으로 작성 가능한 정책과 설정은 계속 만든다.

## Installer의 관찰 가능한 동작

범용 template bootstrap을 그대로 쓰지 말고 실제 선택에 맞게 좁힌다. 다음 계약을 충족하는 간단한 구현이면 충분하다.

1. 명시적 target-root와 장치 프로필로 대상을 지정한다. 테스트도 이 입력을 쓰며 실제 agent home에 접근하지 않는다.
2. `dry-run`과 `status`는 완전한 read-only다. source 누락·깨진 링크·충돌·실패를 성공처럼 출력하지 않으며 상태 불일치는 exit code로도 구분한다.
3. 선택하지 않은 AI의 디렉터리, hooks, 프로젝트 workspace를 생성하지 않는다. hooks는 요청한 동작만 설치하고 현재 버전에서 이벤트 지원을 확인한다.
4. 기존 파일·symlink·디렉터리는 각각 점검한다. 서로 다른 실파일이나 기존 skill 이름과 충돌하면 자동 대체하지 않는다. 통째 스킬 디렉터리 링크는 기존 사용자 스킬을 가릴 수 있으므로 기본은 개별 연결이다.
5. global instruction 파일에 기존 내용이 있으면 해당 플랫폼이 실제 읽는 방식으로 병합한다. 한 플랫폼의 import 문법을 다른 플랫폼에 그대로 넣지 않는다. adapter에 필수 wrapper가 있어도 공통 정책 본문은 하나를 유지한다.
6. 백업은 target 상대 경로와 실행 ID로 구분하여 같은 basename도 충돌하지 않게 한다. 대상이 symlink면 연결 정보와 실체 소유권을 보존하고 링크를 따라 다른 저장소를 수정하지 않는다. 실패하면 이번 적용만 복구할 수 있게 기록한다.
7. 두 번째 apply는 변경 0이다. profile 변경/스킬 제외 시 이번 installer가 소유한 링크만 제거하고 다른 사용자 파일은 보존한다.
8. rollback은 설치 기록의 항목만 되돌린다. 설치 후 사용자가 고친 파일이 있으면 덮어쓰지 말고 충돌로 보고한다. 해당 설치가 만들지 않은 부모 디렉터리나 다른 도구 설정을 삭제하지 않는다.

설치 범위와 Git publish 범위를 섞지 않는다. 새 사용자 자신의 local setup 요청은 확정한 가역 로컬 변경을 진행할 근거가 되지만 원본 저장소 push, public repository 생성, 외부 메시지 발송 권한은 아니다.

## 개인화 유지

선별한 파일마다 소스 revision과 개인화 요지를 남겨 upstream diff를 비교할 수 있게 한다. 원본의 자동 동기화 명령이 새 사용자의 origin을 원작성자 repo로 바꾸지 않게 점검한다. 향후 업데이트에서도 제외한 개인 memory, 회사 전용 도구, 새로 생긴 원본 정책이 유입되면 적용하지 않는다.

인증 정보, 원본 사용자 정책, client 기밀을 프로필 template에 넣지 않는다. 소스가 필요한 private asset을 제공하지 않아도 접근 가능한 스킬만으로 설정을 끝낼 수 있어야 하며, 미완 연동은 별도 상태로 남긴다.
