# 적응형 인터뷰

아래는 질문 은행이며 전부 읽어 주는 설문지가 아니다. 한 번에 하나씩 묻고, 실제 답과 발견한 사실을 구분해 기록한다. 각 단계에 `결정 / 근거 답변 / 관련 파일 / 미정`을 남긴다. 사용자가 “모름”이라고 하면 쉬운 추천과 영향을 설명하고 선택받는다. 긴 자유 답변이 여러 항목을 해결하면 다시 묻지 않는다.

## 장비와 도구

첫 질문 예: “AI 작업에 사용하는 기기 구성이 어떻게 되나요?” 현재 발견한 장치를 짧게 덧붙이고 `지금 기기 한 대 / 여러 기기` 같은 선택을 제공한다.

| 결정할 것 | 후속 질문 조건 | 반영 |
|---|---|---|
| OS, shell, CPU, 메모리, 관리자/설치 권한 | 현재 기기는 실측, 다른 기기만 질문 | 실제 OS installer, 무거운 상주 도구 제한 |
| 한 대 / 여러 대, 주 작업기·상주기 역할 | 여러 대일 때만 | 장치 프로필, 적용 순서 |
| 파일을 기기별 보관 / 한 기기에 두고 원격 편집 | 여러 대일 때만 | Git 동기화와 원격 접속을 별개로 결정 |
| 사용할 AI 도구와 CLI/앱 구분 | 항상 | 실제 로컬 스킬 로드 지원을 확인한 도구만 연결 |
| 언어 입력·원격 화면·접속 편의 | 원격 선택 시만 | 필요한 OS 설정만 |

MacBook 한 대에서도 완결되어야 한다. Windows라면 native/WSL 중 실제 사용 환경을 확인하고 macOS 명령을 실행하지 않는다. 웹 채팅만 쓰며 로컬 스킬을 읽을 수 없다면 파일 정본과 수동 전달 절차까지만 가능하다고 설명하고 CLI 설치 의사를 선택받는다. 도구를 추가 설치한다고 자동 가정하지 않는다.

## 정체성과 명명

이름은 한 묶음의 예시를 보여준 뒤 사용자가 직접 정하도록 한다. 예시는 추천이지 확정값이 아니다.

- AI가 부를 이름/닉네임과 주 대화 언어. 실명·이메일은 필요하지 않으면 수집하지 않는다.
- 개인 SSOT의 표시 이름, 저장소 slug, 실제 저장 위치. 예: 표시명 `나의 작업실`, slug `my-ai-workspace`. 이미 쓰는 폴더가 있으면 그 구조를 우선한다.
- 프로젝트 루트(여러 개/없음 허용), 개인 규칙 정본 파일명, 지식/작업 기록 폴더명, 날짜·branch·skill 명명 규칙. 선호가 없는 값은 제안하고 수락한 것만 확정한다.
- 장치 별칭은 여러 기기일 때만. 현재 OS hostname은 별칭과 별개이며 임의로 시스템 hostname을 바꾸지 않는다.
- 원작성자 회사/닉네임/프로젝트를 발견하면 그대로 유지할 이유가 있는지 확인한다. 새 사용자가 같은 회사에 있어도 개인 계정·고객 프로젝트·봇 ID는 승계하지 않는다.

이름 선택 후 `이전 이름/경로 → 새 이름/경로 또는 삭제 → 영향을 받는 파일` 표를 만든다. 저작권/라이선스 표기와 플랫폼 필수 파일명은 개명 대상에서 구분한다.

## 개인 업무와 정책

“AI에게 자주 맡길 일은 무엇인가요?”부터 묻는다. 개발자 전제를 두지 않는다. 글쓰기, 리서치, 업무 문서, 디자인, 코드, 개인 일정 등 실제 업무에서 필요한 스킬을 연결한다.

| 개인화 축 | 구체화할 내용 |
|---|---|
| 대화 | 언어, 설명 길이, 전문성, 질문 빈도, 결과 보고 형식 |
| 자율성 | 가역 로컬 작업을 맡길 범위, 중요한 미정 선택 처리 |
| Git·공유 | 로컬 전용/사용자 소유 remote, 공개 범위, commit·push·PR 승인 정책 |
| 개발 | 실제 stack, 기존 package manager, worktree, 검증 명령, 배포 환경과 승인 범위; 개발할 때만 |
| 기록 | 필요한 지식·메모·handoff 종류, 보관 위치, 자동/수동 기록, 보존·공유 범위 |
| 프로젝트 분리 | 개인/회사/고객별 규칙과 credential 소유 경계 |
| 비용·리소스 | 유료 도구 허용, 상주 서비스 여부, Docker/동시 작업 자원 제한 |
| 선택 연동 | wiki, GitHub, 원격 접속, 알림, 이메일, 일정, bots; 필요하다고 답한 것만 |

유료 모델명/가격, 최신 OS·AI 설정은 이 가이드에 고정하지 않는다. 선택에 필요할 때 확인한다. 승인 단계를 많이 넣는 것을 좋은 개인화로 간주하지 않는다. 사용자가 원하는 자율성을 명확히 표현하되 플랫폼 권한이나 고객 데이터 소유 경계를 약화하지 않는다.

## 스킬 선택과 최종 빈틈 확인

실제 소스에 존재하는 스킬만 `용도 / 의존 도구 / 원작성자 전용 여부 / 추천`으로 짧게 보여 준다. 각 항목은 `그대로 사용 / 나에게 맞게 수정 / 제외 / 나중에`로 결정한다. 목록이 길면 업무 분야별로 좁혀 묻는다.

마지막 질문 예: “지금까지 정한 것 외에, AI가 꼭 지키거나 피해야 할 본인만의 작업 습관이 있나요?” 답변을 실제 규칙/파일로 연결한다. 인터뷰 요약에서 빠진 필수 결정만 보완하고 적용으로 넘어간다.
