# 수용 시나리오

스킬 작성 시에는 아래 입력으로 다음 질문·생성 계획·권한 경계를 검토한다. 실제 사용자 환경에 적용할 때에는 선택한 프로필의 installer와 생성물을 임시 target root에서 실행한다. 이 두 검증을 혼동하지 않는다.

| 입력 | 기대 행동 |
|---|---|
| MacBook 한 대, Codex만, 글쓰기와 리서치 | 장비 확인 다음 업무·이름 질문. 다른 AI·SSH·원격 화면·회사 hooks·개발 DB를 만들지 않음 |
| 노트북+데스크톱, Claude와 Codex, 서로 다른 사용자 홈 | 장치별 경로, 하나의 공통 정본, 현재 장치만 실측 완료. 다른 장치는 연결 전까지 미검증 |
| Windows, 기존 AI 설정과 같은 이름의 개인 스킬 보유 | native/WSL 확인, macOS 명령 사용 안 함, 기존 내용 보존, 충돌을 dry-run에 표시 |
| 웹 채팅만 사용, 추가 도구 설치를 원치 않음 | 파일 정본·수동 사용 안내까지만 제공, 자동 스킬 연결 완료라고 하지 않음 |
| 폴더는 “나의 AI 작업실”, 규칙은 “작업원칙.md” | 공백/한글 실제 파일 처리, 내부 정본명은 반영, 플랫폼 진입점 이름과 연결은 유지 |
| 원본 작성자와 같은 회사지만 개인 계정/업무가 다름 | 조직 이름 유지 여부만 확인, 원본 봇·고객·메모리·계정은 재사용하지 않음 |
| 인터뷰 중단 뒤 재개, 장치 한 대만 추가 | 저장된 실제 답 재사용, 바뀐 장치 정보만 질문, 기존 적용을 덮지 않음 |
| “전부 추천대로”, 아직 추천 묶음을 보여주지 않음 | 추천안을 먼저 보여줌. 기기/이름 등 실제 선호를 대신 답하거나 공개 push하지 않음 |
| 새 upstream 버전이 원작성자 전용 hook을 추가 | 선택 파일의 변경만 비교, 개인 정책 유지, hook은 자동 활성화하지 않음 |

## 실제 적용 검증

- **구조**: 스킬 frontmatter/이름, Markdown 상대 링크, manifest/JSON 형식, interpreter 문법 검사를 실행한다. 플랫폼에 build/lint/test가 있으면 실제 실행하며 없으면 N/A 이유와 대체 검증을 기록한다.
- **읽기 전용**: 빈 임시 target과 기존 파일이 있는 target에서 dry-run/status 전후 파일·디렉터리 목록 및 hash 동일. root가 없을 때도 생성하지 않음.
- **보존·멱등**: 기존 규칙/skill/설정 sentinel을 넣고 apply→apply. 기존 내용/비소유 항목 보존, 두 번째 변경 0, 현재 정본으로 resolve, 깨진 링크 0.
- **경로**: 공백·한글이 포함된 정본과 target에서 적용. 서로 다른 target root 두 개에서 공통 정본 내용 동일하고 절대경로가 서로 섞이지 않음.
- **원작성자 경로 차단**: 저장 위치 답변 전에는 clone·디렉터리 생성 0건. 설치 후 README·hook·link·config에 원작성자의 상위 폴더가 생기지 않고, 선택한 checkout을 이동해도 재적용으로 새 위치를 resolve함.
- **충돌·실패**: 같은 basename 백업 둘, 기존 symlink, source 누락, 잘못된 프로필을 확인. 실패를 성공 처리하지 않음. 오류 후 복구 가능한 상태.
- **제거·복구**: 스킬 선택 해제 시 소유 링크만 제거. rollback 후 설치 전 상태 복원. 설치 후 수정한 파일은 자동 덮어쓰지 않음.
- **개인화**: 생성물 파일명/본문/metadata/실행 경로에서 원작성자 식별자와 제외한 스킬 참조 검사. 개인 memory와 Git history/원본 remote 유입 0. 필수 저작권 표기는 별도 허용 사유.
- **도구 인식**: 선택된 AI의 새 세션 또는 지원되는 진단으로 정본 규칙과 스킬 로드를 확인한다. 실제 세션 확인이 불가능하면 `파일 연결 검증 완료 / 도구 인식 미확인`으로 남긴다. 현재 대화에 파일이 보인다는 이유만으로 새 설치가 로드됐다고 판단하지 않는다.
- **실제 홈 적용**: 검증한 dry-run의 대상과 허용 범위가 일치하는지 대조하고 apply/status/resolve를 실행한다. 비선택 도구의 디렉터리가 새로 생기지 않았는지 확인한다.

보고는 `프로필 / 검증한 기기·도구 버전 / 실행 명령과 결과 / 미검증 범위 / 복구 위치`로 남긴다. 토큰·실제 고객 자료로 테스트하지 않는다. 테스트용 프로세스나 임시 서버를 만들었다면 같은 작업에서 정리한다.
