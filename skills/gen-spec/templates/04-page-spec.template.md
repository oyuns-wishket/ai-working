# 페이지 명세 템플릿

> 이 템플릿은 4단계 "페이지 명세" 작성을 안내한다.
> 목표 분량: 2,500~3,500 토큰/페이지 (8,750~12,250자)
> 최소 분량: 2,000 토큰 미만이면 섹션 누락으로 판단하고 보완 요청
> 의존: 해당 페이지의 `docs/specs/pages/{NN}-{page-name}.md`를 반드시 Read한 후 진행
> 반복 단위: 페이지 1개 = 페이지 명세 1파일

## 산출물 경로

`docs/specs/page-specs/{NN}-{page-name}/00-page-spec.md`

## frontmatter

```yaml
---
title: "{페이지명}"
stage: "page-spec"
depends-on:
  - "docs/specs/pages/{NN}-{page-name}.md"
created-at: YYYY-MM-DD
status: draft
---
```

## 필수 섹션 (8개, 모두 필수) + 4.5 (페이지 유형 해당 시 필수)

페이지 정의에서 기능 목록, 대상 사용자, 레이아웃 힌트를 참조하여 아래 8개 섹션을 **빠짐없이** 작성한다. 추가로, 페이지가 목록/표·관리자/프로필·계층/트리 유형이면 **섹션 4.5(페이지 유형별 필수 인수조건)** 를 반드시 채운다 — 이 동작 AC가 feature-spec §2로 전파되어 gen-app Phase C 게이트가 검증한다.

### 섹션 1: 페이지 목적

```markdown
## 1. 페이지 목적
- **핵심 가치**: (이 페이지가 사용자에게 제공하는 핵심 가치를 한 문단으로)
- **대상 사용자**:
  - **{역할1}**: (이 역할이 이 페이지에서 하는 일)
  - **{역할2}**: (이 역할이 이 페이지에서 하는 일)
- **진입 경로**:
  - (경로1: 어디서 → 어떻게 진입, 딥링크 포함)
  - (경로2: ...)
- **이탈 경로**:
  - (경로1: 어떤 조건에서 → 어디로 이동)
  - (경로2: ...)
```

### 섹션 2: 사용자 여정

역할이나 시나리오가 다르면 다중 여정(여정 A, B, C...)으로 분리한다. 단일 역할이면 1개 여정.

```markdown
## 2. 사용자 여정

### 여정 A: {시나리오명} ({역할})
| 단계 | 사용자 행동 | 시스템 반응 | 감정 |
|------|-----------|-----------|------|
| 1 | ... | ... | ... |
| 2 | ... | ... | ... |
```

각 여정은 최소 5단계 이상. "시스템 반응"은 구체적 UI 동작을 기술한다 (예: "토스트 알림 표시", "목록 자동 갱신", "프로그레스 바 표시" 등). "감정"은 사용자의 심리 상태를 한 줄로 표현.

### 섹션 3: 기능 간 상호작용

```markdown
## 3. 기능 간 상호작용
| 기능A | 기능B | 상호작용 방식 | 공유 데이터 |
|-------|-------|-------------|-----------|
| ... | ... | ... | ... |
```

이 페이지 내 기능들이 어떻게 연동되는지를 매트릭스로 정리한다. 각 기능 쌍마다 상호작용 방식(이벤트, 상태 공유, 트리거 등)과 공유 데이터를 명시한다.

### 섹션 4: 레이아웃 구조

```markdown
## 4. 레이아웃 구조

### 헤더 영역
(페이지 타이틀, 브레드크럼, 액션 버튼 등)

### 메인 영역
(핵심 콘텐츠 영역의 레이아웃 구조 상세)

### 사이드바 (해당 시)
(필터, 네비게이션 트리, 보조 패널 등)

### 푸터 영역
(페이지네이션, 버전 정보 등)

### 반응형 대응
- **Desktop (≥1280px)**: (기본 레이아웃 설명)
- **Tablet (768px~1279px)**: (변경 사항)
- **Mobile (<768px)**: (변경 사항)
```

각 영역에 들어갈 구체적 컴포넌트와 배치를 서술한다. "해당 없음"이면 명시적으로 "본 페이지는 사이드바를 사용하지 않음"으로 기재.

### 섹션 4.5: 페이지 유형별 필수 인수조건 (디자인시스템 동작 계약 → features.json 전파)

> **결정론적 규칙:** 이 페이지가 아래 유형 중 하나에 해당하면, 그 유형의 **필수 동작 AC**를 이 섹션에 명시하고 **5·6단계(기능 정의/명세)로 그대로 전파**한다. 이 AC들은 gen-app의 ERP 디자인시스템(키트) 표준 동작이므로 — feature-spec §2의 인수조건이 되어 **gen-app Phase C가 실제로 검증**한다(`ds-features` + 행동 게이트). 명세에 없으면 준수 빌드도 누락된다(tmax 회귀). **해당 유형이면 누락 불가** — 끄려면 빌드 후 유지보수 단계에서 호출자가 명시적으로 opt-out한다(스펙 단계에서 미리 끄지 않는다).
>
> 시각 픽셀 스펙(색·간격·hex)은 적지 않는다 — 디자인시스템 SSOT + 선택 design-set이 관장한다. 여기서는 **동작(행동) 계약**만 적는다.

페이지 유형을 식별하고(복수 가능), 해당 행을 이 섹션 표에 채운다:

| 페이지 유형 | 식별 기준 | 필수 동작 AC (그대로 feature-spec §2 AC로 복사) |
|------------|----------|----------------------------------------------|
| **목록/표(list/table)** | 행 단위 데이터를 표로 보여주는 페이지(DataTable) | ① 행 선택: 각 행 좌측 체크박스 + 헤더 전체선택(부분선택 indeterminate), 선택 행 일괄 액션 / ② 인라인 편집·CRUD: 셀 인라인 편집 + 행 추가·삭제·저장, 변경은 저장 시 확인 다이얼로그 경유 일괄 커밋(즉시삭제 금지) / ③ 다중 컬럼 정렬: 헤더 **클릭 누적**(shift 전용 금지) + 각 정렬 칼럼에 순서 배지(1·2·3) / ④ 컬럼별 헤더 필터: 각 칼럼 헤더 안 깔때기 아이콘 → 그 칼럼 전용 필터 팝오버(별도 1차 필터 행 금지; 전역 검색만 FilterBar) |
| **관리자/프로필(admin/profile)** | 프로필 영역·역할/권한 전환이 있는 페이지(ProfileMenu) | ⑤ 프로필 = **우측 사이드 Sheet**(dropdown 아님), 아바타 트리거로 오픈, 신원(사용자명·이메일·활성 역할 배지·소속 조직) 표시 / ⑥ 다중 역할 전환: 보유 역할 목록에서 활성 역할 선택 → **권한·메뉴·프로필 재초기화**(활성 역할이 권한 리졸버 주체) |
| **계층/트리(org/menu hierarchy)** | 조직·메뉴 등 부모-자식 트리 페이지(TreeView/TreeTable) | ⑦ 자식 추가(add-child): 노드 선택 → 하위 노드 생성 시 `parentCode` 배선 → 저장 후 트리 재구성 시 **부모 아래 중첩 표시**(평탄화·재조회 후 자식 사라짐 금지) |

```markdown
## 4.5 페이지 유형별 필수 인수조건

- **해당 페이지 유형**: (목록/표 · 관리자/프로필 · 계층/트리 중 해당 표기, 복수 가능. 어디에도 해당 없으면 "해당 없음 — 표준 그리드/트리/프로필 컴포넌트를 쓰지 않는 페이지"로 명시)

### 필수 동작 AC (→ feature-spec §2로 전파)
- [ ] AC-G1 (목록/표): 행 선택 — 각 행 체크박스 + 헤더 전체선택(indeterminate), 선택 행 일괄 액션 동작
- [ ] AC-G2 (목록/표): 인라인 편집·CRUD — 셀 편집 + 행 추가/삭제/저장, 저장 시 확인 다이얼로그 경유 일괄 커밋
- [ ] AC-G3 (목록/표): 다중 컬럼 정렬 — 헤더 클릭 누적 + 순서 배지(1·2·3)
- [ ] AC-G4 (목록/표): 컬럼 헤더 필터 — 각 칼럼 헤더 깔때기 아이콘 → 그 칼럼 필터 팝오버(별도 필터 행 없음)
- [ ] AC-P1 (관리자/프로필): 프로필 사이드 Sheet — 아바타 → 우측 Sheet 오픈, 신원 표시(dropdown 아님)
- [ ] AC-P2 (관리자/프로필): 다중 역할 전환 — 활성 역할 선택 시 권한·메뉴·프로필 재초기화
- [ ] AC-T1 (계층/트리): 자식 추가 중첩 — 자식 생성 시 parentCode 배선 + 저장 후 부모 아래 중첩 표시
```

(이 페이지에 해당하지 않는 행은 적지 않는다. 해당하는 유형의 AC만 위 형식으로 남긴다.)
