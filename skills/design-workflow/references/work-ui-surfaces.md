# ERP·업무 UI의 가독성과 조작

검토일: 2026-09-15. 업무 UI(등록·검색·수정·승인)의 **표·폼·필터바·키보드 입력·밀도·숫자·권한별 상태**의 판정 기준·예시·검증 항목을 소유한다. 모드·게이트·도구 기본값은 SKILL.md를 따르고, 웹 전반의 정렬·반응형·접근성·성능 기준은 [web-quality.md](web-quality.md), 차트·지표 정의·데이터 정확성은 [data-surfaces.md](data-surfaces.md), 모션 시안 선택과 구현 계약은 [motion-design.md](motion-design.md)를 따른다. 이 문서는 그 규칙을 반복하되 바꾸지 않는다.

업무 UI의 "고도화된 가독성"은 장식이 아니라 **같은 화면에서 더 많은 것을 더 빨리 정확하게 읽고 조작하는 것**이다. 판정 기준은 항상 대표 과업의 완료 시간·오류·재입력이며, 화면이 예뻐졌다는 인상으로 대체하지 않는다.

## 읽는 시점과 범위

1. 주 목적이 업무 UI이면 이 문서 전체를 적용한다.
2. 주 목적이 커머스·B2C·데이터 대시보드·홍보라도 이번 범위에 표·폼·필터바·일괄 작업 중 하나라도 있으면 해당 절을 적용한다. 예: 대시보드의 상세 표는 §1, 예약 폼은 §2.
3. `small-feature`(탭 하나, 열 하나, 필드 하나)도 **해당 컴포넌트가 속한 절의 항목을 전부** 확인한다. 범위 가드(전역 토큰·브랜드·공통 컴포넌트 계약 변경 금지)는 유지하고 강도는 줄이지 않는다.
4. `audit`는 아래 항목을 관찰 기준으로만 사용하고 대화로 보고한다. source write·설치·issue/commit·정본 생성은 하지 않는다(경계의 소유는 SKILL.md `## 작업 분류`).
5. 조사 단계([project-audit.md](project-audit.md))에서 밀도 높은 화면 하나와 폼/상세 화면 하나를 실제로 열고, 기존 표·폼 컴포넌트·토큰·키보드 동작을 기준선으로 남긴 뒤 이 문서를 적용한다. 기존 승인 패턴이 있으면 그 패턴이 우선이며, 이 문서는 빈 자리를 채우고 결함을 판정하는 데 쓴다.

기록 위치: 채택한 규칙·예외는 프로젝트 `DESIGN.md`의 `Work UI decisions`(없으면 Components의 Forms·Tables/lists와 Interaction 항목)과 gate template의 `Work UI evidence` 항목에 남긴다([DESIGN template](../assets/DESIGN.template.md), [gate template](../assets/design-gates.template.md)). 새 문서를 만들지 않는다.

## 1. 표(데이터 그리드)

표는 업무 UI의 주 작업면이다. "정확한 값·검색·업무 처리는 표가 출발점"([data-surfaces.md](data-surfaces.md))이며 카드·차트로 대체하지 않는다.

### 1.1 열 정렬과 숫자

| 데이터 유형 | 정렬 | 규칙 |
|---|---|---|
| 텍스트(이름·품목·메모) | 좌 | 헤더도 좌. 줄바꿈 허용 여부를 열마다 정한다 |
| 숫자(수량·금액·비율) | 우 | 헤더도 우. 같은 열은 같은 소수 자릿수, 천 단위 구분, `font-variant-numeric: tabular-nums`([MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/font-variant-numeric)) |
| 단위 | 헤더 또는 열 단위 | `금액(원)`, `중량(kg)`처럼 헤더에 한 번. 셀마다 단위를 반복하면 자릿수 정렬이 깨진다 |
| 날짜·시간 | 우 또는 좌, 열 내 통일 | 같은 표 안에서 형식(`YYYY-MM-DD`, 시간대) 하나. 상대 시간("3분 전")은 정확한 값과 함께만 |
| 상태(badge) | 좌 또는 중앙, 표 내 통일 | 색 + 텍스트 라벨 또는 아이콘. 색만으로 구분하지 않는다 |
| ID·코드값 | 좌, `white-space: nowrap` | 숫자처럼 보여도 우측 정렬·천 단위 구분·크기 비교 대상으로 취급하지 않는다 |
| 행 액션 | 우 끝 또는 고정 열 | 아이콘만이면 accessible name·tooltip 제공 |

판정:

- 숫자 열의 자릿수가 행마다 다르면(`1,200` / `1,200.5`) 결함이다. 열 단위로 정밀도를 고정한다.
- 음수·감소는 `-1,200` 또는 `(1,200)` 중 프로젝트 관례 하나를 쓰고 색을 보조로만 사용한다.
- 0과 빈 값(null/미수집)을 같은 `0`으로 표시하면 결함이다. 빈 값은 `—` 등 일관된 표시와 의미를 정의한다([data-surfaces.md](data-surfaces.md) 지표 규칙과 동일).
- 통화·백분율·수량이 같은 표에 섞이면 열마다 단위를 헤더에 명시한다.

### 1.2 고정 헤더·고정 열·행 높이·밀도

- 표 높이가 viewport를 넘으면 헤더를 sticky로 고정한다. 고정 헤더가 focus된 셀·anchor를 가리면 결함이다.
- 열 폭 합이 컨테이너를 넘으면 **식별 열(이름·코드) 하나**를 좌측 고정하고 가로 스크롤을 표 영역 안에서만 허용한다. 페이지 전체 가로 스크롤은 결함이다.
- 행 높이는 밀도 단계 토큰으로 정한다. 예: `compact` 32px / `default` 40px / `comfortable` 48px(프로젝트 토큰이 있으면 그 값). 표 하나 안에서 행 높이가 콘텐츠에 따라 흔들리면 줄바꿈 정책을 먼저 고친다.
- 기본 밀도 판정: 한 화면에서 비교·검토하는 행이 많고(≥ 20행) 사용자가 숙련자이면 `compact`가 출발점이다. 입력·검토가 섞이거나 터치 조작이 있으면 두 조건이 함께 성립해도 `default`가 출발점이다(터치 target 크기가 우선). 어느 쪽도 아니면 `default`. 기존 승인 패턴·프로젝트 토큰의 기본 밀도가 있으면 그 값이 우선한다. 밀도 전환 기능은 실제 요구가 있을 때만 추가한다([web-quality.md](web-quality.md)).
- 열 폭은 실제 최장 데이터(긴 한글 거래처명, 최대 금액)로 정하고 헤더 글자 폭으로 정하지 않는다.

### 1.3 정렬·필터·페이지·총계 상태 표시

| 상태 | 사용자에게 보여야 하는 것 | 구현 단서 |
|---|---|---|
| 정렬 | 현재 정렬 열과 방향 | `th[aria-sort]`, 아이콘 + 헤더 강조. 다중 정렬은 우선순위 번호 |
| 필터 | 적용 중인 조건 전부와 개별 해제 | chip/요약 + 초기화. 숨은 기본 필터도 표시 |
| 페이지 | 현재 범위와 전체 수 | `1–50 / 1,234건`. 페이지 크기 변경 시 첫 페이지로 이동 여부를 명시 |
| 총계 | 합계의 범위 | `현재 페이지 합계` vs `조회 조건 전체 합계`를 라벨로 구분 |
| 조회 중 | 기존 데이터 유지 + 갱신 중 표시 | 표 구조를 유지하는 skeleton 또는 overlay. 요청 역전 방지 |

판정:

- 서버 pagination이면 정렬·검색·합계가 **현재 페이지만 대상인지 전체 조건인지** 화면에 명시해야 한다. 명시 없이 현재 페이지만 정렬되면 결함이다([data-surfaces.md](data-surfaces.md) 직접 검증 2와 동일).
- 필터를 바꿨는데 페이지 번호가 범위를 벗어난 채 남으면 결함이다.
- 정렬·필터·페이지 상태가 URL·뒤로가기·새로고침에서 유지돼야 하는지 기존 동작으로 확인하고 보존한다(§3 URL 동기화).

### 1.4 행 선택·일괄 작업

- 선택 열은 첫 열, 헤더 체크박스는 **현재 페이지 전체 선택**이며 "조회 조건 전체 N건 선택"은 별도 명시 동작으로 둔다.
- 선택 수·대상 요약·가능한 일괄 작업을 표 근처 고정 영역에 표시하고 선택 해제 경로를 제공한다.
- 일괄 작업 결과는 성공/실패 건수와 실패 행·사유를 개별로 보여준다. 전체 성공만 가정한 toast는 결함이다.
- 페이지·필터 이동 시 선택이 유지되는지 초기화되는지 정책 하나를 정해 표시한다.

### 1.5 인라인 편집 상태

| 상태 | 표시 | 키보드 | 데이터 |
|---|---|---|---|
| 보기 | 기본 셀 | Enter/F2로 편집 진입 | 서버 값 |
| 편집 중 | 셀 테두리·배경 변경, 입력 focus | Enter 저장, Esc 취소, Tab 다음 셀 | 미저장 값 표시 |
| 저장 중 | 셀 단위 진행 표시, 입력 잠금 | 중복 제출 차단 | 낙관적 표시 여부를 명시 |
| 저장됨 | 짧은 강조 후 기본 셀 | — | 서버 응답 값으로 교체 |
| 실패 | 셀에 오류 표시 + 메시지, 입력값 보존 | focus 복귀 | 재시도·취소 제공 |
| 충돌 | 타인이 먼저 수정했음을 표시 | — | 서버 값과 내 값을 함께 보여주고 선택 |
| 읽기 전용(권한) | 편집 진입 없음, 시각 구분 | Enter 무동작 + 이유 표시 | — |

판정:

- 편집 중 다른 행을 클릭하면 저장/취소/유지 중 정책 하나를 정하고 입력값을 잃지 않는다.
- 실제 응답 전에 "저장됨"을 표시하면 결함이다([web-quality.md](web-quality.md) 조작·피드백).
- 셀 단위 편집과 행 단위 편집을 한 표에서 섞지 않는다.
- 셀 이동·편집 키는 [WAI-ARIA APG Grid 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/grid/)을 기준으로 하되, 기존 accessible primitive가 있으면 그것을 따른다.

### 1.6 빈·오류·권한 없음 상태

- `empty`(아직 없음) / `no results`(조건 불일치) / `error`(실패) / `permission denied`를 구분한다([web-quality.md](web-quality.md)). 표 헤더·필터바는 유지하고 본문 영역에 상태와 다음 행동(조건 초기화, 재시도, 권한 요청 경로)을 넣는다.
- 권한 없음은 열 단위(특정 열 마스킹)와 행 단위(일부 행 비표시)·기능 단위(편집 불가)를 구분해 표시한다. 마스킹된 열은 빈 값처럼 보이지 않게 한다.
- 부분 실패(일부 열 데이터만 실패)는 해당 열에 표시하고 전체 표를 오류 상태로 바꾸지 않는다.

### 1.7 긴 한글·코드값·ID 처리

- 긴 한글 텍스트는 열 단위로 `1줄 truncation + 전체값 접근`(tooltip/상세) 또는 `2줄 clamp` 중 하나를 정한다. 글자 크기를 줄여 맞추지 않는다.
- 코드·ID·전화번호·계좌는 줄바꿈하지 않고 복사 가능하게 한다. 필요하면 monospace를 쓰되 표 전체를 monospace로 만들지 않는다.
- 한글은 `word-break: keep-all` 등 프로젝트 관례를 확인하고 단어 중간 줄바꿈이 의미를 해치는 열(품목명·주소)에서 확인한다.
- 실제 최장 데이터로 캡처하고 헤더·셀 잘림을 검증한다.

### 1.8 모바일 대안

판정:

- 열이 4개 이하이고 행 단위 조회가 목적이면 **카드 변환**(각 행 → label/value 목록)을 허용한다. label을 생략하지 않는다.
- 열이 많거나 행 간 비교가 목적이면 **표 영역 별도 스크롤 + 식별 열 고정**을 유지한다. 320 CSS px에서 페이지 전체가 양방향 스크롤을 요구하면 결함이다([web-quality.md](web-quality.md) 반응형, [WCAG reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)).
- 어느 쪽이든 정렬·필터·선택·일괄 작업·인라인 편집 중 desktop에서 제공하는 기능이 모바일에서 사라지면 그 사실과 대체 경로를 기록한다.

### 1.9 TanStack Table 사용 규칙

- [TanStack Table](https://tanstack.com/table/v8/docs/overview)은 headless 로직(정렬·필터·페이지·선택·컬럼 상태)에만 쓴다. markup·스타일·접근성(`caption`, `th scope`, `aria-sort`, 키보드 이동, focus-visible)은 직접 구현하고 위 규칙으로 검증한다.
- 기존 표 컴포넌트·wrapper가 있으면 재사용한다. 가상화는 대표 데이터 규모에서 실측 후 별도로 선택하고, 선택·focus·내보내기·합계 의미를 보존하는지 검증한다([data-surfaces.md](data-surfaces.md) 직접 검증 5).
- 표 로직 라이브러리·차트 컴포넌트·데이터 수집 시스템을 혼동하지 않는다.

### 1.10 표 검증 항목

각 표마다 다음을 실제 브라우저에서 확인하고 결과를 기록한다.

| 항목 | 방법 | 증거 |
|---|---|---|
| 정렬·자릿수·단위 | 최대·최소·음수·빈 값이 있는 대표 데이터 | 캡처 + 원본 대조 |
| 고정 헤더·열 | 스크롤 끝까지, focus 셀 가림 여부 | 캡처 |
| 정렬·필터·페이지·총계 범위 | 서버 응답과 화면 값 대조 | [data-surfaces.md](data-surfaces.md) 직접 검증 1의 수치 대조 표 |
| 선택·일괄 작업 | 페이지 이동 후 선택 유지 정책, 부분 실패 | 캡처 + 결과 메시지 |
| 인라인 편집 | 저장·실패·충돌·권한 없음 각 상태 | 상태별 캡처 |
| 상태 | empty / no results / error / permission denied | 상태별 캡처 |
| 긴 값 | 최장 한글·코드·ID | 캡처 |
| 모바일 | 320px, 선택한 대안 | 캡처 + 사라진 기능 기록 |
| 키보드 | §4 순서로 조회·이동·편집 완료 | 조작 기록 |

## 2. 폼

### 2.1 라벨·그룹·필수 표시

| 항목 | 기본 | 판정 |
|---|---|---|
| 라벨 위치 | 위(top) | 입력 수가 많고 스캔 속도가 중요한 업무 폼은 좌측 정렬 라벨(left)을 허용하되 폼 전체에서 하나로 통일 |
| placeholder | 힌트만 | 라벨 대체 금지([web-quality.md](web-quality.md)) |
| 그룹 | `fieldset/legend` 또는 동등한 제목 | 5개 이상 입력은 의미 단위로 묶고 그룹 사이 간격 > 그룹 내부 간격 |
| 필수 표시 | 필수 항목에 표시(`*` + 설명) | 대부분 필수인 폼은 "선택" 항목에만 표시하는 역방향 허용. 폼마다 방식 하나 |
| 도움말 | 입력 아래, 오류와 다른 스타일 | 형식(`YYYY-MM-DD`)·단위·예시를 라벨이나 도움말에 명시 |

### 2.2 오류 위치와 복구

- 오류는 해당 입력 바로 아래(또는 옆)에 연결(`aria-describedby`)하고 폼 상단 요약은 오류가 2개 이상일 때 추가한다. 상단 요약의 각 항목은 해당 입력으로 이동한다.
- 제출 실패 시 입력값을 전부 보존하고 첫 오류 입력으로 focus를 옮긴다. 값이 지워지면 결함이다.
- 검증 시점: 제출 시 전체 + blur 시 형식 검증이 기본. 타이핑 중 즉시 오류를 띄우지 않는다(형식이 완성된 뒤에만).
- 서버 오류(중복 코드, 재고 부족)는 필드 오류로 매핑할 수 있으면 해당 필드에, 없으면 폼 상단에 표시하고 재시도 가능하게 한다.

### 2.3 저장·제출 상태

| 상태 | 표시 | 규칙 |
|---|---|---|
| idle | 기본 버튼 | 필수 미입력이면 disabled보다 제출 시 오류 안내를 우선(왜 안 되는지 보이게) |
| submitting | 버튼 진행 표시 + 잠금 | 중복 제출 차단. Enter 연타·더블 클릭 확인 |
| success | 실제 응답 후에만 표시 | 성공 후 이동/초기화/유지 중 정책 하나. 등록 후 연속 등록이 잦으면 "저장 후 새로 입력" 제공 |
| error | 폼에 남고 값 보존 | §2.2 |
| dirty | 변경 있음 표시 | 저장 버튼 활성화 또는 상태 텍스트로 변경 존재를 알린다 |

### 2.4 자동 저장·이탈 경고

- 자동 저장을 쓰면 "저장 중 / 저장됨 HH:MM / 저장 실패"를 눈에 띄는 고정 위치에 표시하고 실패 시 수동 저장 경로를 준다.
- 자동 저장이 없고 dirty이면 route 이동·탭 닫기 시 이탈 경고를 낸다. 저장 완료 직후에는 경고를 내지 않는다.
- 자동 저장과 명시 저장을 한 폼에서 섞지 않는다. 섞어야 하면 어느 필드가 자동인지 표시한다.

### 2.5 키보드 순서·Enter/Tab

- Tab 순서는 시각 순서와 같다. 좌측 라벨 폼에서 열이 두 개이면 행 우선인지 열 우선인지 정해 DOM 순서로 구현한다.
- Enter: 단일 입력 폼은 제출, 다중 입력 업무 폼은 **다음 필드 이동 또는 제출 중 프로젝트 관례 하나**를 확인해 따른다. textarea에서는 줄바꿈이다. 관례가 없으면 제출로 두고 실수 제출을 막기 위한 확인은 파괴적 작업에만 붙인다.
- Esc는 모달 폼 닫기, 인라인 편집 취소. 값이 있을 때 닫으면 §2.4 경고.
- combobox·date picker·수량 stepper는 기존 accessible primitive의 키를 따르고 마우스 없이 값 입력·선택이 가능해야 한다.

### 2.6 날짜·금액·수량 입력 규칙

| 입력 | 규칙 |
|---|---|
| 날짜 | 직접 타이핑과 picker 둘 다. 형식·시간대 표시. 기간은 시작 ≤ 종료 검증과 프리셋(오늘·이번 달 등) |
| 금액 | 숫자 키패드(`inputmode="decimal"`), 천 단위 구분 표시, 저장 값은 숫자. 통화·소수 자릿수를 라벨에 명시 |
| 수량 | 정수/소수 여부, 최소·최대·단위. stepper는 키보드 ↑↓ 지원 |
| 코드·ID | 자동 대문자/형식 변환 시 사용자에게 보이게. 중복 검사는 blur 또는 제출 시 |

### 2.7 권한별 읽기 전용 표시

- 권한이 없는 필드는 `disabled`가 아니라 **읽기 전용 표시**(값은 보이고 복사 가능)로 하고 이유를 tooltip/도움말에 둔다. 폼 전체가 읽기 전용이면 상단에 한 번 알린다.
- 승인 단계에 따라 편집 가능 필드가 달라지면 현재 단계와 편집 가능 범위를 표시한다.
- 권한 없음을 이유로 필드를 숨기면 사용자가 데이터 부재로 오해하지 않게 "권한 필요" 자리표시를 남긴다(정책상 존재 자체를 숨겨야 하면 예외로 기록).

### 2.8 폼 검증 항목

| 항목 | 방법 |
|---|---|
| 라벨·그룹·필수 | 스크린리더 이름 확인, 필수 표시 일관성 캡처 |
| 오류 위치·복구 | 형식 오류·서버 오류 각 1건 재현, 값 보존과 focus 이동 확인 |
| 제출 상태 | 느린 응답(throttle)에서 중복 제출·성공 시점 확인 |
| 자동 저장·이탈 | 실패 유도, dirty 상태에서 이탈 |
| 키보드 | 마우스 없이 처음부터 제출까지 |
| 입력 규칙 | 경계값(0, 음수, 최대, 소수), 시작>종료 |
| 권한 | 읽기 전용 역할로 같은 폼 캡처 |

## 3. 필터바·검색·기간

- **기본값**: 기간 기본(예: 이번 달)·상태 기본을 화면에 표시한다. 숨은 기본 필터로 데이터가 빠져 있는데 사용자가 모르면 결함이다.
- **적용 상태**: 적용 전(입력 중)과 적용 후를 구분한다. 자동 적용이면 조회 중 표시, 수동 적용이면 "적용" 버튼과 미적용 변경 표시.
- **초기화**: 기본값으로 되돌리는 동작 하나. 개별 조건 해제와 전체 초기화를 구분한다.
- **URL 동기화**: 필터·정렬·페이지·검색어를 URL query에 반영하는 것이 기본이다. 새로고침·뒤로가기·링크 공유 시 같은 결과가 나와야 한다. 기존 동작이 URL을 쓰지 않으면 보존하되 부재를 기록한다([web-quality.md](web-quality.md) 조작·피드백).
- **동일 필터 계약**: 같은 화면의 카드·차트·표는 같은 필터·기간·집계를 사용한다([data-surfaces.md](data-surfaces.md)). 한 요소만 다른 범위이면 그 요소에 범위를 명시한다.
- **느린 조회**: 기존 데이터를 남기고 "조회 중·이전 조건 결과"임을 명료하게 표시한다. 요청 순서가 역전돼 오래된 응답이 최신 결과를 덮으면 결함이다.
- **검색**: 검색 대상 필드(이름·코드·메모 중 무엇)를 placeholder나 도움말에 명시한다. 검색어 하이라이트는 결과 열에서만.
- **기간**: 프리셋 + 직접 입력, 시간대, 포함/제외 경계(종료일 포함 여부)를 명시한다. 비교 기간이 있으면 두 기간의 정의를 함께 표시한다.

검증: 필터 변경 → 조회 상태 표시 → 카드·차트·표 동시 반영 → URL 갱신 → 새로고침 후 동일 결과를 한 번의 조작 기록으로 남긴다.

## 4. 키보드 중심 반복 입력

숙련 사용자의 반복 입력(전표·발주·검수)은 키보드만으로 끝나야 한다.

1. **진입**: 화면 진입 시 첫 입력 또는 검색창에 focus(사용자가 선택한 정책). 자동 focus가 스크롤을 튀게 하면 안 된다.
2. **이동**: Tab/Shift+Tab, 표 안에서는 화살표(§1.5), 필드 간 Enter 이동은 §2.5 관례를 따른다.
3. **단축키**: 저장(`Ctrl/Cmd+S` 또는 프로젝트 관례), 새 행 추가, 검색 focus, 다음/이전 레코드처럼 **반복 빈도가 높은 3–5개**만 정의하고 화면에서 확인 가능하게(단축키 안내 또는 tooltip) 한다. 브라우저·OS 기본 단축키와 충돌하면 결함이다.
4. **연속 입력**: 저장 후 다음 입력으로 자동 이동(새 행·다음 레코드·초기화된 폼) 정책을 정한다. 저장 애니메이션이 다음 입력을 막으면 결함이다([motion-design.md](motion-design.md)).
5. **오류 시 focus 복귀**: 검증 실패 시 첫 오류 필드로, 저장 실패 시 마지막 편집 위치로 focus를 되돌리고 입력값을 보존한다.
6. **취소·이어가기**: Esc로 현재 편집만 취소하고 이전 입력은 유지한다.

예시 흐름(발주 등록): 검색창 focus → 품목 코드 입력 → Enter로 결과 선택 → 수량 필드 focus → 입력 → Enter로 다음 행 → … → `Ctrl/Cmd+S` 저장 → 저장 상태 표시 → 새 전표 첫 필드 focus. 이 흐름을 마우스 없이 완료하지 못하면 결함이다.

## 5. 밀도·정보 위계

- **밀도 기준**: 업무 화면은 관련 정보를 한 화면에서 비교할 수 있는 밀도를 우선한다([web-quality.md](web-quality.md)). 판정: 사용자가 결정에 필요한 값을 보려고 스크롤·탭 전환을 반복하면 밀도가 낮은 것이고, 관련 없는 값이 섞여 스캔이 느려지면 위계가 없는 것이다.
- **카드 남용 금지**: 표·목록·폼을 카드로 감싸서 여백·테두리·그림자를 중복하지 않는다. 카드는 서로 다른 성격의 묶음을 구분할 때만 쓴다. 판정: 카드 안에 카드가 있거나 한 화면에 카드 6개 이상이 같은 위계로 나열되면 재검토한다.
- **축 정렬**: 페이지 제목·필터바·표·합계·하단 액션이 같은 좌우 축을 공유한다. 표 안 숫자 열의 우측 축과 합계 행의 축이 일치해야 한다.
- **위계**: 제목 → 필터/조건 → 핵심 표/값 → 보조 정보 → 액션. 주 액션 하나만 강조하고 파괴적 액션은 분리한다.
- **상태 색 + 비색 단서**: 성공·경고·오류·정보 색은 텍스트 라벨·아이콘·위치와 함께 쓴다. 표의 행 배경색만으로 상태를 구분하면 결함이다. 대비는 [web-quality.md](web-quality.md)의 4.5:1 / 3:1 기준.
- **타이포**: 기존 type scale 안에서 표 본문·라벨·보조 텍스트 세 단계 이내로 제한한다. 강조는 굵기와 색 하나로, 크기 증가는 제목에만.

## 6. 모션(업무)

- 도구 기본값은 SKILL.md와 [motion-design.md](motion-design.md)를 따른다: UI 상태·layout·gesture는 Motion. 업무 UI에 적용하는 대표 동작은 **탭 전환, 행 펼침, 갱신 부분 강조, 저장 상태 연결**이다.
- 판정(세 분기, 승인된 패턴·새 표현의 정의는 SKILL.md `## 공통 원칙`이 소유한다):
  1. **승인된 Motion 패턴**(DESIGN.md·구현노트·gate 기록에 사용자 결정이 남아 있음)이 탭·행 펼침·저장 피드백에 있으면 재사용하고 재선택하지 않는다. 재사용 근거를 기록한다.
  2. **기록 없는 기존 코드 패턴**도 새 표현이 아니면 재사용할 수 있다. "기존 코드 패턴 재사용(미승인)"으로 표시하고 원 코드·동작 동일성·새 표현이 아니라는 판정 근거·변경 상태 검증을 연결한다. 판정 기준: 같은 컴포넌트 유형에 같은 동작(구조·순서·타이밍 범위)이 이미 운영 화면에 있고 바뀌는 것이 엔진·구현뿐이면 새 표현이 아니다. 동작·구조·강조 방식이 하나라도 바뀌면 새 표현이다.
  3. **새 표현**(예: 인라인 편집 저장 강조 방식이 처음 정의됨, 기존에 없던 갱신 강조 추가)이면 [motion-design.md](motion-design.md)의 절차대로 공식 실행 예제를 직접 조작하고 같은 콘텐츠·대표 행동으로 **동작 시안 세 개**를 비교해 사용자 선택을 기록한다. 정지 이미지로 대체하지 않는다. 직접 관찰 미완료 시 처리는 [motion-design.md](motion-design.md)의 문장을 그대로 따른다(관찰 없이 채택하는 선택지는 없다).
- 패턴별 `행동 → 보이는 반응 → 완료 상태`, duration/easing 출발점(짧은 업무 피드백은 120–240ms), reduced motion 대안, cleanup·연속 입력 규칙은 [motion-design.md](motion-design.md) `## 업무 UI 모션 패턴` 표가 소유한다. 이 문서는 어느 컴포넌트에 어떤 패턴을 적용할지(탭 → 탭 전환, 행 상세 → 행 펼침, 인라인 편집 저장 → 저장 상태·갱신 강조, 필터 적용 → 카드·차트·표 동기 갱신)만 정한다. 반복 입력을 기다리게 하는 등장 연출·긴 목록의 순차 등장은 이유 없이 넣지 않는다. ERP라는 이유로 표현을 제거하지도 않는다.
- reduced motion·연속 입력·route 재진입 cleanup은 [motion-design.md](motion-design.md) 실제 확인 항목을 그대로 적용한다.

| 2 | 숫자 대조 | 표 합계·페이지 합계·카드·차트 값을 서버 응답/원본 집계와 대조 | [data-surfaces.md](data-surfaces.md) 직접 검증 1의 수치 대조 표(필터/기간, 원본 집계, 카드 값, 차트 값, 표 합계, 일치 여부) |

| 4 | 320 CSS px | 선택한 모바일 대안, 페이지 양방향 스크롤 없음 | 캡처 |
| 5 | 200% 확대 | 텍스트 200%에서 내용·기능 손실 없음([WCAG resize text](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)) | 캡처 |

미실행 항목은 이유와 함께 명시한다. 해당 없는 상태는 "해당 없음(이유)"로 적고 빈칸이나 체크 표시로 채우지 않는다.

## 적용 범위

이 참조는 **업무 UI 목적에서 필수**이며 `small-feature`도 이번 범위에 속한 컴포넌트의 항목을 **전부** 확인한다. 범위는 좁게, 강도는 전부다. 다른 목적의 화면에 표·폼·필터바가 있으면 해당 절을 같은 강도로 적용한다.
