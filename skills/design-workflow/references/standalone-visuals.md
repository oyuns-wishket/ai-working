# 덱·제안서·시각 리포트

웹 개발 외의 시각 산출물을 명시적으로 요청했을 때 읽는다. 숫자 계산·텍스트 요약만 요청했으면 시각 디자인 작업으로 확대하지 않는다. 모드·게이트·도구 기본값은 [SKILL.md](../SKILL.md)를 따르며, 여기서는 덱의 정본·시안 단위·검증·전달 방식을 정한다.

## 모드 판정

| 조건 | 모드·다음 행동 |
|---|---|
| 기존 덱 정본(마스터 슬라이드·DECK.md) 없음; 브랜드 가이드만 있는 경우 포함 | `new`; 제품 인터뷰에서 목적·청중·핵심 메시지 확인 후 절대 게이트 진행 |
| 브랜드·색·서체·톤 교체 | `rebrand`; 절대 게이트와 기존 내용/수치 보존 |
| 기존 구조·정보 위계 개선 | `refactor`; 보존형이면 scoped, 시각 세계관/대표 화면 전면 교체이면 full 게이트 |
| 기존 템플릿의 일부 슬라이드·섹션 추가 | `small-feature`; 정본·대상·인접 패턴 조사, 새 표현 시안과 전체 검증 강도 유지 |
| 문제·개선안만 요청 | `audit`; 기존 렌더·소스 read-only 진단, 설치·산출물/정본 생성·issue/commit 금지 |

기존 덱 정본(마스터 슬라이드·DECK.md)이 있으면 `small-feature`/`refactor`, 없으면 브랜드 가이드가 있어도 `new`이며 브랜드 토큰은 디자인 방향 인터뷰의 입력으로 재사용한다. 명시적인 브랜드 전환 요청은 위 표의 `rebrand`로 판정한다. “간단히 몇 장”이면 수량만 범위 조건으로 사용하며 인터뷰·시안·검증을 면제하지 않는다. `small-feature`도 기존 브랜드·전역 토큰을 보존하면서 조사·새 표현 비교·검증의 강도는 유지한다.

## 작성 순서와 정본

1. 기존 산출물·브랜드·콘텐츠·수치 출처와 실제 요청을 확인한다. 고객 데이터·브랜드 자산은 프로젝트 소유 위치에 두고 public skill에 복사하지 않는다.
2. `new`/`rebrand` 및 full 게이트 대상이면 **제품 인터뷰 → 디자인 방향 인터뷰 → 시각 방향 3개 → 고해상도 시안 정확히 3개 → 구현 잠금 해제** 순서를 지킨다. [gate template](../assets/design-gates.template.md)에 실제 답변·선택·채택/비채택을 기록한다. `ㄱㄱ`·`알아서`는 미제시 시안의 승인이 아니며 모델·reviewer·subagent가 승인하지 않는다.
3. 고해상도 시안은 같은 핵심 메시지/데이터의 대표 표지+핵심 본문을 묶은 composition 정확히 3개로 보여준다. 색만 바꾼 안으로 채우지 않는다. 동적 차트·모션·그래픽이면 같은 세 composition에 실제 동작과 replay/reset을 포함한다. 정적 덱에는 앱 모션 패키지를 강제하지 않는다.
4. 정본은 산출물 디렉토리의 `DECK.md` 또는 동등한 기존 문서를 사용한다. 아래 표의 결정을 기록하고 별도 PRODUCT/DESIGN을 중복 생성하지 않는다. Git 작업의 gate 기록은 기존 구현노트에, 비Git 덱은 `DECK.md`의 `## Gate evidence` 절에 같은 [gate template](../assets/design-gates.template.md)으로 남긴다. 동등한 기존 정본을 쓰면 그 문서의 `## Gate evidence` 절을 사용한다. 승인 전 시안은 분리된 preview 경로에서 준비한다.
5. 필요한 게이트가 풀리면 승인한 composition을 전체 슬라이드로 전개한다. Git이 없으면 worktree는 N/A이며 Git 전용 설치 스크립트를 실행하지 않는다. 사용 가능한 도구와 native 절차로 같은 게이트·검증을 수행한다.

| DECK.md 기록 | 필요한 내용 |
|---|---|
| Product | 목적·청중·핵심 메시지·대표 전달 과업·수용 기준·보존할 내용/수치 출처 |
| Design | palette·typography/fallback·slide grid·비율·밀도·채택/비채택 레퍼런스 |
| Gate evidence | 모드·정본 근거·실제 인터뷰/방향/시안 결정·잠금 해제·scoped N/A 이유 |
| Experience | 차트/모션/그래픽이 있으면 공식 관찰·채택·3개 동작 시안/기존 패턴 재사용 근거·대조(승인 기록 없으면 미승인 표시); 정적 요소는 N/A |
| Verification and delivery | 아래 전 페이지 검사·증거 표·미실행 이유·파일/URL·남은 한계 |

## 렌더 검증과 전달

1. lint/build가 있는 산출물이면 프로젝트 명령을 실행한다. 없으면 그 부재를 기록하고 전 페이지 실제 렌더로 치환한다. 기존 앱 코드가 포함되면 해당 앱 검사를 생략하지 않는다.
2. 아래 표의 해당 검사를 전 슬라이드에 실행하고 [verification.md](verification.md)의 공통 증거 형식으로 DECK 또는 기존 기록에 남긴다. 승인 시안과 같은 비율·내용·theme·state에서 대조하고 스크린샷 각 쌍에 페이지·조건을 적는다. 렌더 도구가 없으면 미실행으로 보고하고 렌더 검증 완료를 주장하지 않는다.

| 검사 | 직접 확인할 내용 | 통과 기준 |
|---|---|---|
| 전 페이지 렌더 | 표지·본문·마지막 슬라이드까지 넘기기 | 페이지 누락·빈 화면·깨진 넘김 없음 |
| 비율·내용 | 목적에 맞는 투사/열람 비율, 긴 제목·본문·각주 | overflow·잘림·겹침 없이 메시지/출처 읽기 가능 |
| 타이포·자산 | 한글/영문 font fallback·대비·이미지/차트 로드 | 누락 글리프·자산 없음; 의도한 위계·정렬 보존 |
| 수치 | 원본 데이터와 합계·단위·기간·범례/도표 대조 | 출처와 수치 의미 일치; screenshot만으로 통과 금지 |
| 동작·접근성 | 해당 링크·키보드 넘김·차트/모션/그래픽 조작·reduced motion | 대표 과업 완료, 동작/읽기 경로 보존 |
| HTML·export | 실제 지원 desktop/mobile 열람과 전달할 export 형식 다시 열기 | 제공 형식에서 내용·폰트·자산·동작 계약 유지 |

3. HTML이면 해당 산출물 디렉토리만 로컬 HTTP 서버로 서빙하고 200 응답을 확인한 접근 가능한 VPN/LAN URL을 제공한다. 폴백은 실행 중 머신에서 확인한 로컬 호스트명이며 접근 가능 여부·한계를 명시한다. 한글 경로를 인코딩하고 `open` 성공만으로 전달 완료를 판정하지 않는다. 자원을 띄우기 전에 설치된 `dev-protocol`의 local operations를 따른다.
4. 사용자에게 확인할 URL/파일, 승인 시안 대비 차이, 실제 검사·미실행·남은 한계를 전달한다. Markdown은 파일 링크로 제공한다. 작업 종료/리뷰 완료 시 이번 작업이 띄운 서버를 정리하고 다른 세션의 서버는 건드리지 않는다.
