# 덱·제안서·시각 리포트

웹 개발 외의 시각 산출물을 명시적으로 요청했을 때만 읽는다. 숫자 계산·텍스트 요약만 요청한 경우에는 시각 디자인 작업으로 확대하지 않는다.

- 같은 모드를 적용한다: 새 산출물은 `new`, 브랜드 교체는 `rebrand`, 기존 구조 개선은 `refactor`, 기존 템플릿 일부 추가는 `small-feature`, 진단은 `audit`.
- 신규·리브랜딩은 목적·청중·핵심 메시지 인터뷰, 디자인 방향 인터뷰, 3방향 선택, 선택된 방향의 고해상도 시안 3개 승인 후 구현한다. 앱이 아니거나 Git이 없다는 이유로 게이트를 줄이지 않는다.
- 시안은 대표 표지와 핵심 본문을 사용하고 승인 뒤 전체로 확장한다. 단순 색 변경을 세 composition으로 세지 않는다.
- 정본은 산출물 디렉토리의 `DECK.md` 등 기존 형식을 사용한다. Git이 없으면 worktree는 N/A이고 Git 전용 설치 스크립트는 실행하지 않는다. 이미 사용 가능한 도구와 native 작업으로 진행한다.
- lint/build가 없으면 전 페이지 실제 렌더, 비율·폰트·대비·overflow·이미지/차트 누락·넘김 동작으로 검증을 치환한다.
- HTML 결과는 해당 디렉토리만 로컬 HTTP 서버로 서빙하고 200 응답을 확인한 접근 가능한 VPN/LAN URL(폴백: 실행 중인 머신에서 확인한 로컬 호스트명)을 제공한다. 한글 경로를 인코딩하고 `open`에만 의존하지 않는다. 작업 종료/리뷰 완료 시 이 작업의 서버를 정리한다. Markdown 문서는 파일 링크로 제공한다.
- 고객 데이터·브랜드 자산은 해당 프로젝트 소유 위치에 유지한다. public skill에 복사하지 않는다.
