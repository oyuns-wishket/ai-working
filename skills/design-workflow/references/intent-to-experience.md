# 평범한 요청을 도메인에 맞는 디자인 제안으로 바꾸기

사용자가 명칭을 모르거나 “화려하게”, “게임처럼”, “요즘 같은 느낌”으로 요청하면 읽는다. 분석 결과를 사용자가 이해하고 선택할 수 있는 제안으로 바꾸며, 프롬프트 작성이나 도구 조사를 사용자 숙제로 넘기지 않는다. 이 절차는 메인 스킬의 요구 확정 단계에 포함된다.

## 분석하고, 필요한 경우에만 보완

1. 현재 요청·이전 답변·PRODUCT/DESIGN·실제 route와 컴포넌트에서 도메인, 주요 사용자, 핵심 과업, 유지할 계약과 원하는 인상을 찾는다. stack·기존 자산·모바일·호스팅·접근 가능한 도구도 필요한 범위에서 확인한다. 관찰과 추정을 구분한다.
2. 결과를 바꾸는 빈칸만 찾는다. 특히 “보기만 하는 장면”인지 “내 조작으로 시점·구조·결과를 바꾸는 장면”인지 구분한다. 사용자에게 shader나 엔진을 고르게 하지 않는다.
3. 목적·대상 구간·원하는 반응·제약이 충분히 명확하면 요청문 재작성/선제안은 생략한다. 추론한 구현 세부사항은 짧게 알리고 진행한다. **이 생략은 아직 필요한 신규 방향·시안 승인을 생략한다는 뜻이 아니다.**
4. 중요한 경험 선택이 남으면 실행 가능한 추천과 차이가 있는 대안만 제안한다. 필요한 사용자 결정은 기존 인터뷰/방향 선택에 합치고, 확정된 질문은 반복하지 않는다. 기술 수치·일상적인 구현 선택은 에이전트가 맡는다.

## 선택할 수 있는 말로 제안

각 제안은 **쉬운 이름 → 화면에서 일어나는 일 → 통용 명칭 → 도메인에 맞는 이유 → 실제 reference/미리보기 → 비용·모바일·제작 차이**를 짧게 담는다. 명칭은 검색과 대화를 돕는 보조 정보다. 스타일 이름만 나열하거나 유명 사이트를 그대로 복제하겠다고 약속하지 않는다.

| 사용자 표현 | 제안할 경험과 명칭 예 | 도메인에 연결할 판단 |
|---|---|---|
| “제품이 영화처럼 등장했으면” | 빛과 카메라로 제품을 드러내는 **Cinematic product reveal** | 커머스 hero의 소재·특징을 전달; 옵션 선택이 필요하면 별도 조작 구간 |
| “내리면 건물 속이 보이게” | 외피가 열리고 단면·설명이 이어지는 **Scroll-driven cutaway / Scrollytelling** | 건축·설비 이해; 관람/직접 단면 조작에 따라 전달 방식 분기 |
| “마우스에 반응해서 살아 있는 느낌” | 사진·로고 입자가 흩어졌다 모이는 **Interactive particles / Shader effects** | 브랜드·B2C의 인상; 복잡한 3D 모델 없이도 후보 가능 |
| “게임 같은 사이트” | 공간 이동 **Explorable world** 또는 배치·조립 **Interactive playground** | 탐색 자체가 목적인지, 짧은 참여 장면인지 구분 |
| “ERP인데 눈에 들어오고 멋있게” | 상태·숫자가 연결되는 **Data storytelling / UI motion** | 실제 지표·필터·업무 피드백 우선; 공정 설명만 별도 그래픽 가능 |

예시는 고정 업종별 스타일이 아니다. ERP라는 이유로 표현을 약화하거나 B2C라는 이유로 모든 화면을 게임화하지 않는다. 모바일·구매·입력 과업과 브랜드 의도를 함께 판단한다. 필요한 graphics 후보는 [graphics-production.md](graphics-production.md)에서 고른다.

## 제안 요청문과 승인 연결

보완이 필요하면 아래 내용을 짧은 자연어 요청문으로 만들어 사용자가 그대로 선택·수정할 수 있게 한다. 새 문서를 강제하지 않고 기존 구현노트/DESIGN에 확정 결과만 남긴다.

> [사용자/도메인]의 [목표]를 위해 [대상 구간]을 [쉬운 느낌·연출 명칭]으로 구성한다. 사용자가 [행동]하면 [보이는 변화]가 일어난다. [기존 기능/디자인]을 유지하고, [모바일·접근성·예산/호스팅] 조건을 충족한다. 추천 전달 방식은 [이유를 포함한 후보]이며, [미확정 선택]을 시안에서 비교한다. 완료는 [관찰 가능한 행동·결과]로 확인한다.

- 원래 요청과 달라지거나 새로 추정한 부분은 제안문에서 **변경·추가 부분만 굵게** 표시하고 이유를 설명한다. 조용히 자유 회전을 영상 재생으로 바꾸지 않는다.
- 새 디자인은 기존 세 방향 설명에 이 제안을 통합한다. 방향 선택 뒤의 세 composition에 실제 동작을 넣는다. “프롬프트 승인 → 연출 승인 → 도구 승인” 같은 별도 연속 게이트를 만들지 않는다.
- scoped 작업은 기존 정체성과 승인 패턴을 유지한다. 중요한 새 경험만 해당 구간에서 비교·선택하며 이미 명확한 작은 수정에는 제안 묶음을 만들지 않는다.
- reference 링크는 경험을 설명하는 근거이고 실제 시안 승인을 대신하지 않는다. 사용자가 느낌을 모르겠다면 직접 재생·클릭·스크롤해 볼 시안과 AI 추천을 제공한다.
- 읽기 전용 `audit`에서는 분석·제안을 대화로만 제공하고 종료한다. 설치·시안 파일·공통 스킬 수정으로 확장하지 않는다.
