# Motion과 Anime.js를 사용하는 웹 모션 설계

웹 UI 작업에서 모션 설계는 기본 항목이다. ERP·커머스·B2C라는 업종과 별도로 페이지의 과업과 브랜드 톤을 판단한다. 신규 상호작용에는 Motion을 기본으로 사용하고, 애니메이션·인터랙션 연출 요청에는 Anime.js를 준비해 해당 연출에 연결한다. 게이트·도구 기본값과 규칙 소유는 [SKILL.md](../SKILL.md)를 따른다. 이 문서는 모션 도구 선택·과업별 추천·시안 선택·구현 계약·무료/유료 사용·모션 검증의 상세를 소유한다. 설치·재사용은 [tooling.md](tooling.md), 서비스별 권한 판정은 [tool-capabilities.md](tool-capabilities.md), 3D runtime·scroll 소유권·자산 파이프라인은 [motion-and-3d.md](motion-and-3d.md)를 따른다.

## 과업별 추천

| 현재 과업 | AI가 추천할 동작 | 확인할 결과 |
|---|---|---|
| ERP·관리자 반복 처리 | 탭 이동, 행 펼침, 갱신 부분 강조, 저장 상태 연결 | 입력을 방해하지 않고 변경과 완료를 이해함 |
| 커머스 탐색·비교 | 상품 이미지·옵션 전환, 상세 진입, 필터·장바구니 반응 | 선택한 상품과 현재 위치를 유지함 |
| 결제·예약·가입 | 단계 진행, 오류 위치, 제출 중·실제 완료 피드백 | 중복 제출·입력 유실 없이 과업을 끝냄 |
| B2C 콘텐츠·커뮤니티 | 상세 확장, 저장·좋아요, 메뉴·피드 전환 | 읽기 흐름과 반응의 맥락을 유지함 |
| 브랜드·제품 소개 | 순차 등장, 장면 전환, 선택적 scroll story | 메시지와 CTA를 발견하고 이해함 |

같은 쇼핑몰에서도 히어로·상품 목록·결제는 다른 강도를 사용할 수 있다. 같은 과업에는 차분한 프리미엄·친근함·역동성 등 브랜드의 표현을 반영한다. 업종을 이유로 전체 화면을 정적 또는 화려한 모션으로 고정하지 않는다.

버튼/카드의 press·선택, 탭 표시와 패널, 목록/테이블 변경, 모달/드로어, 폼의 loading/error/success 중 해당하는 동작을 계획에 포함한다. 큰 목록의 긴 순차 등장, 반복 업무를 기다리게 하는 연출은 선택 이유가 있어야 한다. 결제·예약 성공은 실제 응답 이후 표시한다.

## 공식 예제 관찰과 채택 기록

1. 새 방향이면 과업에 맞는 공식 실행 예제를 찾아 브라우저에서 직접 조작한다. 제작 도구의 예제 원본이면 해당 도구에서 열어 재생·회전하고, 웹 전달 후보도 브라우저에서 확인한다. 제작 도구 안에서의 검수만으로 웹 공식 예제 관찰 완료를 기록하지 않는다. 완료 조건은 [SKILL.md의 공통 원칙](../SKILL.md#공통-원칙)을 따른다.
2. **예제 URL → 직접 조작한 행동 → 관찰 결과 → 이번 시안에 채택할 표현 → 접근 불가 시 대체 근거와 한계** 순서로 기록한다. 공식 예제와 제작자 사례를 구분하고, 관찰한 표현만 채택 근거로 쓴다.
3. 직접 관찰이 미완료이면 새 방향의 최종 채택과 application source 구현을 보류한다. 접근 가능한 실행본이 있으면 결정을 묻지 않고 직접 조작한다. 접근 불가(URL 응답 실패·로컬 실행 실패의 실제 근거)가 확인된 경우에만 사용자에게 접근 가능한 공식 실행본 확보·공식 소스의 로컬 실행·해당 방향 보류 중 하나를 결정받는다. 대체 자료와 진행 요청은 직접 관찰 완료를 대신하지 않는다.
4. 승인된 패턴의 작은 수정이면 기존 관찰·선택 근거를 링크하고 변경한 상태를 대조한다. 새 표현이면 아래 시안 선택을 수행한다. `small-feature`는 대상 구간만 좁히고 조사·시안(새 표현일 때)·검증의 강도를 유지한다.
5. 접근 실패이면 실제 시도한 URL·로컬 실행 명령과 오류, 실제 확인한 공식 영상·문서·소스, 확인하지 못한 입력·성능을 아래 표에 적는다. 문서 읽기·설치·외부 링크 제공·자체 제작 시안을 공식 예제의 직접 동작 관찰로 기록하지 않는다. 준비를 계속하면 분리된 preview 경로만 사용하고 미관찰 방향은 미확정으로 표시한다.
6. 기록은 기존 DESIGN/구현노트의 해당 결정에 연결한다. 기록 없는 기존 패턴의 재사용은 [SKILL.md의 공통 원칙](../SKILL.md#공통-원칙)으로 판정하고, 새 표현이 아니면 `기존 코드 패턴 재사용(미승인)`으로 표시해 원 코드·동작 동일성·새 표현 아님 판정 근거·변경 상태 검증을 연결한다. `small-feature`의 범위 가드와 검증 강도는 그대로 유지한다. `audit`이면 이 절 전체를 읽기 전용 조사에만 적용하고 로컬 실행본 준비·시안·기록 파일 생성·설치를 하지 않는다.

| 예제 URL | 직접 조작한 행동 | 관찰 결과 | 이번 시안에 채택할 표현 | 접근 불가 시 대체 근거와 한계 |
|---|---|---|---|---|
| 실제 URL·관찰일·공식/제작자 구분 | 입력·시작 상태·왕복/초기화 등 실행한 행동 | 시작/전환/완료의 관찰과 증거 위치 | 대상 구간·채택할 상태 연결/표현 | 접근 성공이면 해당 없음; 실패이면 시도 URL/명령·오류·실제 대체 자료·미확인 항목·확보/로컬 실행/보류 결정 |

이 표는 [verification.md](verification.md)의 공통 관찰 표에 연결하는 상세 자료다. 예제 URL·행동·관찰·채택은 공통 표의 같은 항목에 대응하고, 대체 근거/한계는 URL·관찰에 함께 남긴다. 대조 결과는 아래 실제 검증 결과를 연결해 갱신한다. 같은 증거를 별도 문서에 중복 작성하지 않는다.

## 모션을 모르는 사용자와 선택하기

1. 기존 답변·디자인·대표 과업에서 원하는 느낌을 파악한다. 추가 결정이 필요하면 “빠르고 차분하게 / 부드럽게 이어지게 / 브랜드가 드러나게”처럼 묻는다. easing·spring 수치를 사용자에게 결정시키지 않는다.
2. AI가 한 방향과 이유를 추천한다. 예: “상품 탐색은 부드럽게 연결하고 결제는 짧게 반응하도록 추천합니다.”
3. 새 차트·모션·그래픽·3D 방향을 제작할 때는 해당 소유 참조의 **공식 실행 예제 직접 관찰 → 채택할 표현 지정 → 같은 데이터/콘텐츠로 동작 시안 정확히 세 개 → 결과 대조**를 따른다. 정지 이미지·외부 링크만으로 대체하지 않는다. 모션·차트·그래픽·3D가 들어가는 동적 시안은 **실제 동작**(재생/초기화, 클릭·필터·스크롤 조작)을 반드시 포함한다. 기본 축은 빠른 반응·부드러운 연결·브랜드 표현이며 프로젝트에 맞게 구성한다. 각 안의 상태 연결·공유 요소 이동·강조와 완료 피드백 중 과업에 맞는 차이를 실제 동작으로 보여준다. 이름·배치·duration만 바꿔 세 안을 채우거나, 정지 이미지·외부 예제 링크만 제시하지 않는다.
4. 재생·초기화와 직접 클릭/스크롤을 제공한다. 신규 디자인에서는 기존 composition 세 시안 안에 통합한다. 기존 디자인에서는 해당 컴포넌트/흐름만 비교한다.
5. “B인데 더 빠르게”, “카드는 B, 결제는 A” 같은 실제 답을 토큰·패턴으로 바꾸고 채택·수정 근거를 기록한다. 사용자가 모르면 먼저 체험할 수 있게 하며 임의로 취향을 확정하지 않는다.

이미 승인된 패턴을 작은 변경에서 재사용할 때는 재선택을 요구하지 않는다. 새 표현이 필요한 경우만 비교한다. [SKILL.md](../SKILL.md)의 승인의 정의·사용자 메시지 해석표·부분 승인과 재제시 조건을 모두 충족하면 그 범위에서 결정한다. 시안과 구현은 [SKILL.md](../SKILL.md)의 잠금·승인 경계를 유지한다. `ㄱㄱ`·`알아서`는 미제시 시안의 승인이 아니며 모델·reviewer·subagent는 사용자 대신 승인하지 않는다.

선택 표시 이동 → 관련 값/콘텐츠 전환 → 안정된 완료 상태를 하나의 행동으로 설계한다. hover와 pin의 우선순위, 같은 항목 재선택, pointer exit, Escape/초기화, 연속 입력 중 취소·이어가기를 실제 과업에 맞게 정한다. 긴 페이지의 선택 표시나 공유 요소는 scroll 좌표와 진행 중인 이동도 고려해 잘못된 항목으로 튀지 않게 한다.

## 업무 UI 모션 패턴

아래 duration/easing은 새 패턴을 비교할 **권장 출발점**이며 외부 라이브러리 성능 보장이 아니다. 기존 승인 토큰이 있으면 그것을 우선한다. 짧은 업무 피드백은 **120–240ms** 안에서 시작하고 실제 반복 입력·브랜드 의도·사용자 선택으로 조정한다. 연출을 기다려야 다음 입력이 가능하면 상태 처리와 연출을 분리한다. scroll story의 길이는 이 시간 범위에 맞추지 않는다. `ease-out`은 입력 직후 빠르게 반응해 정착하는 표현, `ease-in-out`은 두 상태가 이어지는 표현의 출발점이다.

| 패턴 | 행동 → 보이는 반응 → 완료 상태 | 권장 duration / easing 출발점 | Reduced motion 대안 | Cleanup·연속 입력 규칙 |
|---|---|---|---|---|
| ERP 탭 전환 | 탭 클릭/키보드 선택 → 선택 표시와 패널 연결 → 활성 탭·패널·URL이 기존 계약대로 일치 | 표시 120–180ms / ease-out, 패널 180–240ms / ease-in-out | 표시 위치와 패널을 즉시 전환; 선택·focus 유지 | 이전 패널 이동 취소; 마지막 선택을 반영하고 이전 응답이 덮어쓰지 않게 함; unmount 시 listener 해제 |
| 행 펼침 | 행 상세 열기 → 해당 행과 상세의 공간 연결 → 선택 행의 상세와 펼침 상태 일치 | 180–240ms / ease-out | 높이 이동 없이 상세 즉시 표시; 펼침 상태 안내 | 빠른 열기/닫기는 현재 상태에서 이어감; 행 제거·가상화 재사용 시 animation/측정 listener 해제; stable row ID와 focus 보존 |
| 갱신 강조 | 데이터 갱신 수신 → 바뀐 셀/행과 갱신 상태 강조 → 정확한 값·갱신 시각이 안정적으로 남음 | 강조 진입/복귀 각각 120–240ms / ease-out; 읽기 유지 시간은 별도 결정 | 이동·점멸 대신 정적 갱신 표시·텍스트; 색만으로 알리지 않음 | 다음 갱신 때 이전 timer/강조 취소·재설정; unmount 후 오래된 강조·값 반영 금지 |
| 저장 상태 | 저장 클릭 → 처리 중과 중복 제출 방지 → 실제 응답 뒤 저장됨 또는 입력을 보존한 오류·재시도 | 상태 전환 120–180ms / ease-out; 요청 대기는 실제 응답 기준 | 회전/이동 대신 처리 중·완료·오류 텍스트 즉시 표시 | 떠난 화면에 완료 animation/toast를 중복 생성하지 않음; timer/listener 해제와 오래된 응답 무시; 전환 완료를 서버 성공으로 취급하지 않음 |
| 모달/드로어 | 열기 → backdrop과 패널 진입·focus 이동 → 내용 조작 가능; 닫기 → 퇴장 → 호출 위치로 focus 복귀 | 진입 180–240ms / ease-out, 퇴장 120–180ms / ease-in-out | 이동 없이 열기/닫기; focus와 배경 차단 계약 유지 | 빠른 재열기 때 오래된 퇴장 callback 취소; modal의 focus trap·scroll lock·listener를 닫힘/unmount에서 해제; 비모달은 focus trap 강제 금지 |
| 필터 후 카드·차트·표 동기 갱신 | 필터 적용 → 선택 조건·조회 중 상태를 함께 표시 → 카드·차트·표가 같은 필터/집계 결과로 정착 | UI 상태 120–180ms / ease-out, 연결 전환 180–240ms / ease-in-out; 데이터 준비 시간과 분리 | 정확한 최종값·조건·갱신 상태 즉시 표시; 숫자 보간·geometry 이동 제거 | 이전 요청 취소 또는 응답 무시; 적용 조건/결과 버전 일치 후 완료 표시; 차트 geometry는 차트 담당, Motion은 주변 UI만 제어 |

1. 패턴을 적용하면 `행동 → 보이는 반응 → 완료 상태`를 실제 route와 데이터로 구체화한다. 표에 나온 상태가 없는 컴포넌트에 억지로 추가하지 않는다.
2. 필터 결과가 부분 도착하면 각 영역에 조회 중/이전 결과임을 명시한다. 새 조건과 오래된 값을 같은 완료 결과로 보이지 않게 한다. 값·집계 검증은 [data-surfaces.md](data-surfaces.md), 표·폼·키보드·권한 계약은 [work-ui-surfaces.md](work-ui-surfaces.md)를 따른다.
3. 기존 패턴을 재사용하면 인접 UI와 변경 상태를 조사·검증한다. 승인 기록이 없으면 위 절의 `기존 코드 패턴 재사용(미승인)` 근거를 남긴다. 새 표현이면 위 공식 관찰과 동작 시안 정확히 세 개를 수행한다. 작은 범위에서도 브랜드·전역 토큰 변경 없이 전체 검증 매트릭스를 적용한다.

## 구현 계약

| 대상 | 기본 담당 | 적용 방식 |
|---|---|---|
| UI 상태·layout·gesture | Motion | 설치된 stack의 API, layout/공유 요소/등장·퇴장 패턴 |
| 요청된 SVG·순차 연출·복합 timeline | Anime.js | 컴포넌트 scope, timeline, cleanup까지 실제 연결 |
| 3D scroll scene 연출 | Anime.js timeline 또는 이미 progress를 소유한 Motion | native page scroll·필요 시 CSS sticky; runtime 연결·제어권은 [motion-and-3d.md](motion-and-3d.md) |
| 복잡한 scroll 요구의 기록된 예외 | GSAP ScrollTrigger | 아래 공식 문서·실측·DESIGN 기록 조건을 모두 충족한 경우에만 선택 |

도구 선택은 위 기본값을 따른다. GSAP은 Anime.js onScroll/Motion useScroll로 구현 불가한 기능을 공식 문서·실측으로 확인하고 DESIGN에 예외로 기록한 경우에만 추가한다. GSAP은 기존 의존성이라는 이유만으로 기본값으로 승격하지 않는다. 예외이면 구현 불가한 기능·확인한 공식 문서·실측 조건/결과·대안·담당 속성과 공존 종료 범위 또는 유지 계약을 기록한다. smooth-scroll 도구는 기본 설치하지 않는다. [GSAP ScrollTrigger](https://gsap.com/docs/v3/Plugins/ScrollTrigger/)는 예외 검토 근거이며 renderer가 아니다.

Anime.js 연출 요청이 오면 설치 여부만 확인하고 끝내지 않는다. 기존 API로 해당 연출을 구현하거나 없는 경우 로컬 설치한다. 설치 위치와 시점은 [tooling.md](tooling.md)의 앱 라이브러리 설치·재사용을 따른다. 게이트 전 시안 의존성은 분리된 preview 경로에만 준비하고, 앱 source·package/lockfile은 구현 잠금 해제 후 변경한다. `audit`이면 설치·구현하지 않는다. 두 도구를 쓰면 예를 들어 Anime.js는 hero timeline, Motion은 메뉴·카드의 상태를 맡긴다. 동일 속성에 두 엔진을 연결하지 않는다. 사용자 요청 전체가 기존 Motion 패턴 재사용이고 새 연출이 없으면 불필요한 Anime.js 의존성을 추가하지 않는다. 승인 여부는 재사용 근거와 별도로 기록한다.

라이브러리의 기능 수를 채우려고 연출을 추가하지 않는다. 이미 사용 중인 SVG 완료 표시도 실제 행동에 연결되고 cleanup되면 유효한 역할이다. chart geometry·UI layout·숫자 glyph처럼 소유 대상을 나누고, 공식 extension이 있으면 overlay를 그 경로에 연결해 좌표·clip·등장 단계를 보존한다.

React에서는 기존 `framer-motion`/`motion` 버전·import·공통 wrapper를 먼저 확인한다. 호환되는 기존 구성을 사용하고 두 패키지를 중복 추가하거나 요청 없이 major upgrade하지 않는다. 기존 semantic markup·폼 상태·focus·가상화 계약을 유지한다. 비React에서는 공식 해당 stack 경로를 확인하고 불가능한 API를 복사하지 않는다.

DESIGN 정본에 페이지별 강도와 timing/easing/distance/spring, 반복·연속 입력 정책, reduced motion, 엔진별 대상, 선택한 시안과 재사용 범위를 남긴다. 코드의 기존 토큰/패턴 저장 위치를 사용하며 모든 프로젝트에 같은 wrapper 구조를 강제하지 않는다.

## 무료·유료

Motion 코어의 무료 기능으로 기본 상태·layout·scroll을 구현할 수 있다. Motion+의 접근 권한이 있으면 선택한 예제·프리미엄 기능을 활용하되, 팀/사용 범위와 실제 접근을 확인한다. 유료 계정이 없으면 무료 예제·코어 구현을 사용한다. 유료 소스의 접근 제한을 우회하지 않는다. 전용 Three.js 통합 같은 별도 premium/early-access API를 무료 안정 기능으로 가정하지 않는다. 플랜·가격은 스킬에 고정하지 않는다.

## 실제 확인

[verification.md](verification.md)는 공통 실행 순서·증거 형식과 목적별 검증 요약을 소유하고, 이 절은 모션의 상세 수용 기준을 소유한다. 두 검사를 함께 적용한다. `audit`이면 이미 사용 가능한 화면·도구로 관찰하고 미실행 항목을 보고한다.

1. 프로젝트에 정의된 lint/typecheck/test/build와 detector·브라우저 매트릭스를 verification 순서로 실행한다. 실제 import·사용 코드·엔진별 대상 속성을 확인한다. 설치만 확인하면 구현 검증 미완료다.
2. 같은 route·viewport·data·theme·인증/선택 상태에서 승인 시안/기존 패턴과 실제 구현을 대조한다. 대표 과업을 mouse/touch/keyboard로 시작 → 전환 → 완료까지 실행하고 직접 조작·재생 증거를 남긴다.
3. 같은 항목 재선택, 빠른 연속 입력, 반대 동작, Escape/초기화, loading/error 재시도를 실행한다. 마지막 입력과 최종 상태가 다르거나 focus·입력·데이터를 잃으면 실패다. 필터 동기 갱신이면 원본 집계와 카드·차트·표의 값도 대조한다.
4. OS reduced motion을 초기 로드와 실행 중 설정 변경 모두에서 확인한다. Motion·커스텀 JS·CSS·3D·영상 전체에 반영하고 수동 설정이 있으면 OS 전환 후에도 사용자 선택을 보존한다. 공간 이동·숫자 보간을 제거해도 정확한 값·선택·완료 피드백은 남아야 한다. 모바일에서는 hover 없이 핵심 행동을 끝낸다.
5. unmount·route 이탈/재진입과 빠른 열기/닫기를 반복한다. timeline·listener·timer·callback이 중복되거나 제거된 대상에 실행되면 실패다. 공유 상태/자원은 실제 소유자만 해제한다.
6. 성능 영향 여부는 [verification.md의 모드별 검증 매트릭스](verification.md#모드별-검증-매트릭스)로 판정한다. 영향이 있으면 기기·브라우저·network·cache·데이터 규모·측정 도구/구간을 기록하고 입력 반응·frame time을 전후 측정한다. 선언한 duration은 실제 반응 시간 측정값이 아니다.
7. 누락한 승인 표현이 있으면 범위 내 원인을 수정하고 해당 검사와 영향받은 검사를 반복한다. 필요한 검사가 불가능하면 공백과 영향을 남기고 검증 완료로 표시하지 않는다. 자동 검사는 사용자의 인상 평가를 대신하지 않는다.

아래 상세 표는 [verification.md](verification.md)의 공통 검증 표 `결과`에 증거로 연결한다. 공통 표의 명령/route·조건·통과/실패/미실행/N/A·미실행 사유를 대체하지 않는다.

| 대표 행동·비교 조건 | 승인 시안/기존 패턴의 기대 | 실제 시작/전환/완료 관찰·증거 | 판정 | 수정·재검증 또는 미실행 한계 |
|---|---|---|---|---|
| route·viewport·data/state·입력 | 채택한 표현과 보존 계약 | 동작 URL/재생 기록·값·실측 | 반영 / 조정 / 누락 / 미실행 | 차이 이유·검사 결과·남은 영향 |
