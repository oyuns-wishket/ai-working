# 도구의 무료·유료 기능을 실제 작업에 연결하기

외부 제작 서비스·프리미엄 예제·모델 공급원을 선택할 때 읽는다. 사용 가능한 기능을 먼저 활용하고, 계정 확인을 별도 장기 인터뷰로 만들지 않는다. 설치는 [tooling.md](tooling.md), 그래픽 제작은 [graphics-production.md](graphics-production.md), 모델 제작은 [ai-assisted-3d.md](ai-assisted-3d.md)를 따른다.

게이트·도구 기본값·규칙 소유는 [SKILL.md](../SKILL.md)를 따른다. 이 문서는 서비스별 무료/포함 유료 기능·권리·지출·실행 가능성 판정의 상세를 소유한다. 특정 계정 권한이 있다는 사실은 기본 엔진 변경이나 미승인 기능 추가의 근거가 아니다. `audit`이면 기존 자료·연결 상태만 읽고 설치·생성·export·publish·기록 파일 쓰기를 하지 않는다.

## 서비스별로 필요한 작업만 확인

“유료 구독 중”은 해당 서비스에 관한 사용자 진술이다. 다른 서비스의 구독이나 모든 기능·API·무제한 사용을 뜻하지 않는다. 현재 요청에 필요한 작업을 아래처럼 나눠 확인한다.

| 기능 | 확인할 내용 |
|---|---|
| 생성·편집 | 텍스트/이미지 생성, 기존 모델 수정, 재질·부품·애니메이션 편집 가능 여부 |
| 내보내기·배포 | 로컬 build와 export/download/publish 권한을 분리; 영상·프레임·GLB·vector/원본 형식, script 서명과 runtime 수용 여부, 표현/상태 보존 범위 |
| 사용 권리 | 해당 asset의 상업 사용·수정·귀속표시·배포 조건; 상품 상표/외형 권리는 별도 확인 |
| 브랜딩 | 워터마크·서비스 로고 제거 가능 여부 |
| 호스팅 | 서비스 embed, 자체 asset 호스팅, runtime까지 독립 실행이 각각 가능한지 |
| 연결 | 현재 사용할 수 있는 앱·MCP·API·CLI; 웹 구독에 API 사용이 포함되는지 |
| 이용량 | 이번 작업에 필요한 크레딧/한도와 별도 과금·초과 사용 여부 |

모든 공급원을 조사하지 않는다. 필요한 기능을 충족할 후보부터 전체 흐름 **입력 → 제작 → 수정 → export → 사용 권리 → 웹 운영**을 확인한다. 생성 화면이 무료여도 다운로드나 상업 납품까지 무료인지는 별개다.

## 확인 근거와 실행

1. 기존 대화와 프로젝트 결정을 재사용한다. 이미 알려진 서비스·사용 가능 범위를 다시 묻지 않는다.
2. 현재 연결된 도구, 설치된 앱의 지원 기능, 프로젝트 설정과 공식 문서를 확인한다. 계정이 필요한 경우 이미 승인된 연결의 상태/기능 정보만 읽는다. 토큰·브라우저 쿠키·계정 파일을 광범위하게 검색해 구독을 추정하지 않는다.
3. 근거를 `사용자 진술`, `현재 공식 문서`, `연결 도구/실제 실행 확인`, `미확인`으로 구분한다. 일반 가격표와 사용자의 실제 접근 권한을 혼동하지 않는다.
4. 현재 작업 범위에서 사용 가능하고 추가 결제 없는 포함 기능은 바로 활용한다. 이미 허용된 생성·수정마다 재승인을 받지 않는다. 잔여 한도와 입력의 외부 전송 범위를 확인한 뒤 실행한다. 기능 접근 권한과 작업 승인을 구분한다. 시안 제작 중이면 분리된 preview에서 실행하고, 앱 반영은 SKILL.md의 잠금 해제 뒤에 한다. export 권한이 있어도 publish·외부 공개는 그 작업이 이미 승인된 범위에서만 실행한다.
5. 미확인 기능에 의존해야 하면 필요한 정보 하나만 질문한다. 예: “Spline의 export 메뉴에서 자체 호스팅 다운로드를 사용할 수 있나요?” 기다리는 동안 자산 후보·콘셉트·무료 로컬 초안을 준비한다.

최초 생성은 작은 배치로 시작하고 실행 전 해당 배치의 포함 이용량/예상 소모와 추가 과금 없음을 확인한다. 결과가 나쁘면 관찰한 결함을 수정할 근거를 먼저 만들고, 같은 방식이 연속 두 번 실패하면 재생성을 멈추고 자산·제작 경로를 재평가한다. 사용자 피드백에 따른 후속 수정도 남은 승인 범위와 한도 안에서 수행한다.

권한 확인은 사용자가 구독명을 기억하는 시험이 아니다. 접근 가능한 도구에서 직접 확인하고, 직접 볼 수 없는 항목만 사용자에게 짧게 요청한다. 비밀번호·토큰을 대화로 보내게 하지 않는다.

## 선택 분기

| 현재 상태 | 확인 근거 유형 | 에이전트가 이어서 할 일 |
|---|---|---|
| 필요한 유료 기능이 현재 포함되고 실행 가능 | 현재 공식 문서의 작업별 권한 + 연결 도구/실제 실행 확인; 사용자 진술만이면 실행 가능 여부는 미확인 | 이번 요청의 허용된 비용/이용량 안에서 생성·편집·export·연동까지 수행 |
| 무료 기능만 사용 가능 | 현재 공식 문서의 무료 출력/권리 조건 + 연결 도구/실제 실행 확인 | 권리·출력·품질·호스팅 요구를 충족하는 무료 경로 선택 |
| 웹 구독은 있지만 API는 별도 과금 | 사용자 진술과 현재 공식 문서의 웹/API 구분 + 현재 연결 경로 확인 | 사용 가능한 앱/MCP/로컬 export 경로 확인; API 결제를 포함으로 취급하지 않음 |
| 구독/한도 확인 불가 | 미확인으로 표시; 사용자 진술·현재 공식 문서·연결 도구 중 부족한 근거를 특정 | 비용 없는 준비를 진행하며 실행에 필요한 사실 하나만 확인 |
| 한도 소진·권한 거부 | 연결 도구/실제 실행의 오류 + 현재 공식 문서 또는 사용 가능한 상태 정보 | 같은 오류를 반복 호출하지 않고 원인 확인 후 동등한 무료 경로로 전환 |
| 무료 경로가 중요한 요구를 충족하지 못함 | 무료 샘플의 실제 실행/출력 결과 + 필요한 권리/기능의 현재 공식 문서; 비용 미확인이면 명시 | 실제 대안의 결과·비용·일정 차이를 보여주고 달라지는 결정만 받음 |

무료 대체가 같은 모델 품질·상업 권리·호스팅·편집 가능성을 만족하면 승인된 범위에서 계속 진행한다. 고유 제품을 일반 모델로 바꾸거나 자체 호스팅을 외부 embed로 바꾸는 것은 동등한 대체가 아니다. 이용 가능한 대안을 구체화한 뒤 선택받는다.

구독 업그레이드·추가 구매·별도 API 결제·자동 초과 사용은 기존 구독 사용과 구분한다. 새로운 지출이 필요한 경우에만 대상·금액/한도·결과물을 제시하고 그 지출 승인을 받는다. 시안 제작 권한만으로 미승인 고객 자료를 외부 서비스에 업로드하지 않는다.

## 사용자가 직접 결제하고 돌아오는 경로

유료 대안이 요구를 더 잘 충족하면 먼저 리뷰 가능한 비교를 제공한다. **지금 가능한 무료/포함 경로의 결과·한계**, **유료로 얻는 구체적인 품질/편집/export/호스팅 차이**, **현재 공식 가격·과금 단위/예상 한도·일회성/반복 비용**, **AI 추천과 이유**를 보여준다. 가격을 확인할 수 없으면 미확인으로 표시한다. 무료 경로로 충분할 때도 불필요한 결제를 유도하지 않는다.

사용자가 유료 경로를 선택하면 공식 결제/기능 안내 링크와 필요한 최소 작업을 안내하고 **사용자가 직접 결제·계정 연결**하도록 한다. 결제정보·비밀번호를 받거나 대신 결제하지 않는다. 기다리는 동안 선택한 결과물을 보존하고 비용 없는 준비만 진행한다. 복귀하면 새로 가능해진 기능과 승인된 범위의 실제 export를 확인한 뒤 **기존 결정·원본에서 이어서** 제작·웹 연결한다. publish는 기존 공개 승인 범위 안에서만 확인·실행하고, 미승인이면 권한 상태를 읽고 preview/export까지 검증한다. 인터뷰와 시안 선택을 초기화하지 않는다. 결제 완료 진술을 무제한 API·초과 과금 허용으로 확대하지 않는다.

## 자주 혼동하는 경계

- **Motion**: 기본 라이브러리와 Motion+ 예제/프리미엄 컴포넌트는 구분한다. 접근 가능한 유료 권한이 있으면 목적에 맞는 보유 예제·기능을 활용하고, 없으면 무료 코어·예제로 완성한다. [Motion 문서](https://motion.dev/docs/react), [Motion+](https://motion.dev/plus)
- **Bklit UI**: chart 코드와 Studio 편집 도구의 라이선스가 다르다. 해당 코드·도구의 조건을 각각 확인한다. [공식 저장소와 라이선스](https://github.com/bklit/bklit-ui)
- **Spline**: 웹 embed와 GLB export, 코드 다운로드와 완전 self-host, AI 생성 크레딧은 별도 기능이다. GLB가 씬의 이벤트·조명·후처리를 그대로 보존하지 않는다. [가격/기능](https://spline.design/pricing), [GLB export](https://docs.spline.design/exporting-your-scene/files/exporting-as-gtlf-glb), [self-host](https://docs.spline.design/exporting-your-scene/web/exporting-as-self-hosted-project)
- **Hana**: Spline의 그래픽 canvas이며 viewer/embed·영상·이미지 등 export와 실제 plan 권한을 확인한다. Spline Desktop MCP 연결 가능 여부와 cloud AI 전송/크레딧도 별개다. [Hana export](https://docs.spline.design/hana-a-canvas-for-interactivity/assets-and-export/exporting-in-hana), [Desktop MCP](https://docs.spline.design/generate/spline-mcp-server)
- **Rive**: editor의 export 플랜과 CLI의 로컬 제작/build를 같은 권한으로 취급하지 않는다. CLI/MCP의 실제 지원 버전, 편집 원본·`.riv` 출력, 계정이 필요한 export/publish, script 서명·watermark·웹 runtime 조건을 각각 확인한다. 로컬 preview 성공이나 구독만으로 상업 웹 배포/무워터마크 사용이 보장되지 않는다. [CLI](https://rive.app/docs/cli/overview), [시작/배포 조건](https://rive.app/docs/cli/getting-started), [MCP](https://rive.app/docs/editor/ai/mcp), [editor 가격](https://www.rive.app/pricing)
- **Lottie·게임 엔진**: player/engine의 오픈소스 권리와 가져온 animation·template·asset, 유료 editor·비공개 프로젝트·cloud hosting 조건을 분리한다. [Lottie source/license](https://github.com/airbnb/lottie-web), [PlayCanvas plans](https://playcanvas.com/plans)
- **전문 DCC·스트리밍**: Cinema 4D/Houdini의 제작 권한과 최종 산출물 권리를 확인한다. Houdini Apprentice는 상업 납품 무료 경로로 가정하지 않는다. Pixel Streaming의 GPU 서버·동시 접속·전송 운영 비용은 engine 이용 조건과 별도다. [Houdini 조건](https://www.sidefx.com/get/try-houdini/), [Pixel Streaming](https://dev.epicgames.com/documentation/unreal-engine/overview-of-pixel-streaming-in-unreal-engine)
- **Meshy·Tripo**: 무료 생성 체험이 다운로드·상업 사용·API를 모두 허용한다고 가정하지 않는다. Meshy는 무료 다운로드 대상/횟수·귀속표시·API 과금을, Tripo는 다운로드 자격과 생성 모델의 상업 사용 조건을 확인한다. [Meshy 무료 범위](https://help.meshy.ai/en/articles/15696428-what-is-included-on-the-free-plan), [Meshy API](https://docs.meshy.ai/en), [Tripo 다운로드](https://www.tripo3d.ai/help/features/why-cant-i-download-my-model), [Tripo 상업 사용](https://www.tripo3d.ai/help/privacy-policy/how-to-use-tripo-models-commercially)
- **Blender·외부 자산**: Blender 사용 비용과 가져온 모델·텍스처·HDRI의 권리는 별개다. 오픈소스 생성 모델도 가중치·지역·배포 제한을 확인한다. Hunyuan 계열 자체 호스팅을 조건 확인 없이 무료 기본값으로 추천하지 않는다. [Blender 사용 권한](https://www.blender.org/about/)

가격·플랜명별 기능·크레딧 수량을 이 문서에 고정하지 않는다. 채택 시 공식 자료와 실제 이용 가능한 범위를 다시 확인하고 확인일을 남긴다.

## 기능 권한과 납품 검증

[verification.md](verification.md)는 공통 실행 순서·증거 형식과 목적별 검증 요약을 소유하고, 이 절은 외부 기능 판정의 상세를 소유한다. 제작 품질·동작은 [graphics-production.md](graphics-production.md) 또는 [ai-assisted-3d.md](ai-assisted-3d.md)에서 검증한다.

1. 선택한 도구/작업별로 `사용자 진술`, `현재 공식 문서`, `연결 도구/실제 실행 확인`, `미확인`을 구분한다. 공식 문서의 일반 플랜 설명만 있으면 실제 계정 접근을 확인했다고 기록하지 않는다.
2. 승인된 입력·비용 범위 안에서 작은 제작→수정→export 샘플을 실행한다. 로그인/GUI가 필요하면 에이전트가 수행할 수 없는 정확한 작업만 요청하고 독립적인 비용 없는 준비를 계속한다.
3. 실제 출력 형식·재편집 가능성·워터마크·필요 귀속표시·배포 위치가 선택한 납품 계약과 일치하는지 대조한다. 다운로드 성공은 상업 사용 권리의 증거가 아니므로 해당 권리 근거를 별도로 연결한다.
4. 최종 웹에서 asset·decoder/runtime 요청과 호스팅 의존성을 확인한다. 계획에 없던 서비스 의존성이나 제한된 export가 있으면 동등 대체 여부를 판단하고 달라지는 선택만 받는다.
5. 실제 실행 실패·권한 부족·한도 소진이면 선택 분기로 돌아간다. 현재 공식 문서를 확인할 수 없으면 기존 사실의 유효성을 새로 검증했다고 주장하지 않고 해당 권리/비용 의존 실행은 확인될 때까지 보류한다. 비용 없는 로컬 준비는 계속한다.
6. 검증을 통과한 범위와 미확인 범위를 분리한다. preview 성공이나 결제 완료 진술만으로 납품 권리·호스팅·웹 통합 완료를 보고하지 않는다.

아래 상세 표는 [verification.md](verification.md)의 공통 검증 표 `결과`에 증거로 연결한다. 공통 표의 명령/route·조건·통과/실패/미실행/N/A·미실행 사유를 대체하지 않는다.

| 도구/작업 | 확인 근거 유형·날짜 | 필요한 권리/형식/호스팅 | 실제 실행·출력 증거 | 판정·다음 경로 |
|---|---|---|---|---|
| 생성/편집/export/웹 전달 중 해당 작업 | 사용자 진술 / 현재 공식 문서 / 연결 도구·실제 실행 확인 / 미확인 | 해당 작업에 필요한 조건만 | 익명화한 결과·자산/웹 검증 링크 | 가능 / 실패 / 미확인·잔여 결정 |

## 기록 범위

프로젝트 `DESIGN.md` 또는 기존 결정 기록에는 **도구/작업, 채택 이유, 확인 근거·날짜, 납품 형식/호스팅, asset 라이선스·출처, 대체 경로**만 정리한다. [DESIGN template](../assets/DESIGN.template.md)을 재사용한다.

개인 구독 상세·계정 식별자·키·잔여 크레딧 화면은 공개 저장소에 기록하지 않는다. 필요한 계정 설정은 기기 로컬에 둔다. “사용 가능한 포함 기능으로 수행, 추가 비용 없음”처럼 익명화한 실행 판단과 납품에 필요한 권리 근거는 남길 수 있다.
