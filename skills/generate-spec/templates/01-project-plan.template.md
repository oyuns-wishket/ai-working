# 프로젝트 계획서 템플릿

> 이 템플릿은 1단계 "프로젝트 계획서" 작성을 안내한다.
> 목표 분량: 2,000~3,000 토큰 (7,000~10,500자)
> 최소 분량: 1,500 토큰 미만이면 보완 요청

## 산출물 경로

`docs/specs/01-project-plan.md`

## frontmatter

```yaml
---
title: "{프로젝트명}"
stage: "project-plan"
depends-on: []
created-at: YYYY-MM-DD
status: draft
---
```

## 필수 섹션 및 작성 가이드

### 1. 프로젝트 개요

사용자에게 다음을 질문하여 채운다:
- "이 프로젝트의 배경과 필요성은 무엇인가요?"
- "프로젝트의 목표를 알려주세요. 정량적 목표가 있다면 포함해주세요."
- "프로젝트 범위 — 다루는 것과 명시적으로 다루지 않는 것은?"

```markdown
## 1. 프로젝트 개요
- **배경 및 필요성**: (현재 상황의 문제점, 왜 이 프로젝트가 필요한지)
- **목표**:
  - (정성 목표)
  - (정량 목표 — 수치, 기간, 측정 기준 포함)
- **범위**:
  - **다루는 것**: (포함 항목 bullet list)
  - **다루지 않는 것**: (제외 항목 + 사유)
```

### 2. 대상 사용자

사용자에게 질문: "이 시스템을 사용할 사용자 유형들을 알려주세요. 각 유형의 역할, 목표, 핵심 태스크를 포함해주세요."

```markdown
## 2. 대상 사용자

| 사용자 유형 | 역할 | 목표 | 핵심 태스크 |
|------------|------|------|------------|
| {유형1} | ... | ... | ... |
| {유형2} | ... | ... | ... |
```

최소 2개 이상의 사용자 유형을 정의한다. 각 유형마다 역할, 목표, 핵심 태스크가 구체적으로 기재되어야 한다.

### 3. 핵심 요구사항

사용자에게 질문:
- "비즈니스 관점에서 반드시 충족해야 할 요구사항을 알려주세요."
- "성능, 보안, 접근성 등 비기능 요구사항이 있나요?"

```markdown
## 3. 핵심 요구사항

### 비즈니스 요구사항
- **BR-1**: (요구사항 상세)
- **BR-2**: (요구사항 상세)

### 비기능 요구사항
- **NFR-1 (성능)**: (구체적 수치 — 응답 시간, 동시 사용자 등)
- **NFR-2 (보안)**: (인증, 권한, 데이터 보호 등)
- **NFR-3 (접근성)**: (WCAG 레벨, 지원 범위 등)
```

BR/NFR 번호를 부여하여 이후 단계에서 참조 가능하게 한다.

### 4. 제약 조건

사용자에게 질문: "일정, 예산, 기술, 규제 등 제약 조건이 있나요?"

```markdown
## 4. 제약 조건
- **일정**: (마일스톤, 데드라인)
- **예산**: (해당 시)
- **기술적 제약**: (기존 시스템, 호환성, 기술 스택 제한 등)
- **규제/컴플라이언스**: (개인정보보호법, PCI-DSS 등 해당 시)
```

### 5. 용어 정의

사용자에게 질문: "이 프로젝트에서 사용하는 도메인 전문 용어가 있나요? 약어, 업계 용어 등을 알려주세요."

```markdown
## 5. 용어 정의

| 용어 | 정의 | 비고 |
|------|------|------|
| {용어1} | ... | ... |
| {용어2} | ... | ... |
```

최소 5개 이상의 도메인 용어를 정의한다. 이후 모든 산출물에서 이 용어 테이블을 기준으로 일관된 용어를 사용한다.

### 6. 디자인 방향성

사용자에게 질문:
- "디자인 원칙이나 톤앤매너 방향이 있나요? (미니멀, 데이터 중심, 친근한 등)"
- "컬러, 타이포, 컴포넌트 라이브러리 등 디자인 가이드라인이 있나요?"
- "참고하고 싶은 벤치마크 서비스나 레퍼런스 UI가 있나요?"

```markdown
## 6. 디자인 방향성

### 디자인 원칙
- (톤앤매너: 예 — "전문적이고 신뢰감 있는, 데이터 중심 인터페이스")
- (UX 원칙: 예 — "3클릭 이내 핵심 태스크 완료", "초보자도 10분 내 온보딩")

### 디자인 가이드라인
- **컬러**: (Primary/Secondary/Accent 방향, 다크모드 여부)
- **타이포**: (서체 방향, 한글/영문 조합)
- **간격/레이아웃**: (8px 그리드 등)
- **컴포넌트**: (사용 예정 라이브러리 — Ant Design, MUI, Tailwind 등)

### 레퍼런스
- {서비스명1}: {URL} — (참고 포인트)
- {서비스명2}: {URL} — (참고 포인트)
```
