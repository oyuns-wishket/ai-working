# 기능 정의 템플릿

> 이 템플릿은 5단계 "기능 정의" 작성을 안내한다.
> 목표 분량: 300~500 토큰/기능 (1,050~1,750자). 페이지당 묶어서 1파일.
> 최소 분량: 200 토큰/기능 미만이면 설명 부족 경고
> 의존: 해당 페이지의 `docs/specs/page-specs/{NN}-{page-name}/00-page-spec.md`를 반드시 Read한 후 진행
> 반복 단위: 페이지 1개 = 기능 정의 파일 N개 (기능당 1파일)

## 산출물 경로

페이지의 기능들을 개별 파일로 생성:
`docs/specs/features/{NN}-{page-name}/{MM}-{feature-name}.md`

번호(MM)는 페이지 명세의 기능 목록 순서 기반.

## frontmatter (개별 기능 파일)

```yaml
---
title: "{기능 제목}"
stage: "feature-definition"
depends-on:
  - "docs/specs/page-specs/{NN}-{page-name}/00-page-spec.md"
created-at: YYYY-MM-DD
status: draft
---
```

## 작성 가이드

페이지 명세의 "기능 간 상호작용" 테이블과 "핵심 기능 목록"(페이지 정의에서)을 참조하여 각 기능을 정의한다.

```markdown
# {기능 제목}

- **설명**: (이 기능이 하는 일을 2~3문장으로)
- **우선순위**: 높음 / 중간 / 낮음
- **컴포넌트 힌트**: (테이블, 폼, 모달, 카드, 차트, 아코디언, 위저드 등)
- **정렬 순서**: {MM}
- **관련 기능**: (같은 페이지 내 상호작용하는 기능 이름 나열)
- **예상 복잡도**: low / medium / high
```

각 기능의 설명은 구체적이어야 한다:
- 너무 추상적: "사용자가 목록을 조회한다"
- 구체적: "정산 회차를 상태(계산중/검토 대기/승인 대기 등)별로 필터링하고, 기간·채널 조건과 결합하여 페이지네이션된 목록으로 조회한다"
