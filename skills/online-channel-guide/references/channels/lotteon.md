# 롯데온 (LotteON Open API) — 온보딩 카드

| 항목 | 값 |
| --- | --- |
| 내부코드 | `lotteon` |
| 온보딩 등급 | `SELF` |
| 확인일 | 2026-07-31 |
| 출처 | `openapi.lotteon.com` 실측, 롯데ON 스토어센터, 연동 솔루션사 가이드 |

## 1. 선행조건

롯데온 판매자(스토어센터) 계정. `3rd`

## 2. 신청 경로

롯데ON 스토어센터 로그인 → `판매자정보` → **OPEN API 관리** → `정보설정` →
**서버 IP 등록**(복수는 세미콜론 `;` 구분) → `키발급`. `3rd`

## 3. 심사·리드타임

심사 없음. 화면에서 즉시 발급. `3rd`

## 4. 발급 결과물

API 키 1개. 헤더 `Authorization: Bearer {api_key}`로 전송한다.
⚠️ **이 방식만 통과한다** — raw 값, 쿼리파라미터, 다른 헤더명은 전부 401. `live`

## 5. 키 수명·회전

⚠️ **인증키 유효기간 1년.** `3rd` 발급 즉시 만료일을 캘린더·모니터링에 등록한다.

## 6. 네트워크 요건

**고정 IP 필수.** 정보설정 화면에서 서버 IP를 등록한다. 401 응답 시 키 오류와
IP 미등록을 함께 의심한다. `live`

## 7. 권한·스코프

별도 scope 선택 화면 미확인. 거래처(`trNo`) 단위로 부여된다. `unknown`

## 8. 역할 분담

| 주체 | 할 일 |
| --- | --- |
| `[USER]` | 스토어센터 로그인, IP 등록, 키 발급 |
| `[AI]` | Bearer 어댑터, identity 확인, 하루창 수집 구현, fake 테스트 |
| `[3RD]` | 고객사 계정이면 담당자의 IP 등록·키 발급 |

## 9. 첫 호출 검증

**전용 health 엔드포인트가 있다.**
`GET /v1/openapi/common/v1/identity` → `{"returnCode":"0000","data":{"trNo":...}}`.
키와 IP가 살아있는지 즉시 판정할 수 있다. 온보딩 직후 이걸 먼저 친다. `live`

## 10. 함정

- **조회창은 반드시 1일 이내(같은 날).** 초과하면 `returnCode=2003`. 하루 창
  (`day+"000000"` ~ `day+"235959"`)으로 1콜씩 돈다. `live`
- **에러 판정은 HTTP가 아니라 `returnCode`로 한다.** `"0000"`만 성공. `live`
- 429(호출한도)는 HTTP 429와 `returnCode=429` **양쪽으로** 올 수 있다. 짧은 백오프로 재시도. `live`
- ⚠️ **079(출고/회수지시 조회)는 상태가 바뀌어도 원지시만 반환한다.** 현재 상태의
  truth는 **086(배송상태 조회)**이다. 이걸 혼동하면 상태가 영원히 갱신되지 않는다. `live`
- 응답의 목록이 top-level로 오기도 하고 `data`로 래핑되기도 한다. 양쪽 방어. `live`
- 발주확인 = 셀러오피스 `주문확인처리` = 080 `SellerIfCompleteInform`에 `ifCplYN=Y`.
  outer `returnCode=0000`과 `data.rsltCd=0000`을 **둘 다** 확인하고, 086에서
  `12/10/DV`로 재조회된 요청만 완료 처리한다. `live`
- 상태 코드: `11` 출고지시(PAID) / `12` 상품준비(PREPARING) / `13` 발송완료(SHIPPING) /
  `14` 배송완료·`15` 수취완료(DELIVERED) / `21`~`27` 취소·회수(CANCELLED). `live`
- 셀러 화면의 `발송지연`과 동일한 read 정의는 공식 조회 API에서 확정되지 않았다.
  090의 `type=S`는 30일 이상 장기미발송이라 의미가 다르다. 가짜 `0` 대신 `—`. `live`

## 11. 폴백
