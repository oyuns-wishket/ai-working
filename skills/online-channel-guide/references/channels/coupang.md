# 쿠팡 (Coupang Wing) — 온보딩 카드

| 항목 | 값 |
| --- | --- |
| 내부코드 | `coupang` |
| 온보딩 등급 | `SELF` (판매자 화면에서 즉시 발급, 권한 활성만 지연) |
| 확인일 | 2026-07-31 |
| 출처 | 쿠팡 Open API 개발자센터 `developers.coupangcorp.com`, 연동 솔루션사 가이드 다수 |

## 1. 선행조건

- 쿠팡 Wing **판매자 등록 + 사업자 인증** 완료. `3rd`
- ⚠️ **사업자 인증을 하지 않은 일반회원은 API 키 발급 자체가 불가.** `3rd`

## 2. 신청 경로

Wing 로그인 → `판매자정보` → `추가판매자정보` → **OPEN API 키 발급** → `발급` →
`OPEN API` 선택 → 약관 동의 → `Key 발급받기` → 업체 입력 방식에서
**자체개발(직접입력)** 선택 → 업체명·URL·**IP 주소** 입력. `3rd`

## 3. 심사·리드타임

- 심사 없음. 키 자체는 즉시 발급. `3rd`
- ⚠️ **실제 access 권한 활성화는 내부 절차로 최대 24시간 소요될 수 있다.** `3rd`
  발급 직후 401/403이 나도 즉시 설정 오류로 단정하지 말고 24시간 경과 후 재확인한다.

## 4. 발급 결과물

`업체코드(vendorId)`, `Access Key`, `Secret Key` 3종. 화면에서 복사. `3rd`

## 5. 키 수명·회전

- 만료 정책 **미확인**. 재발급 절차는 존재한다(솔루션사 안내 기준). `unknown`
- 인증은 요청마다 **HMAC 서명**을 생성하는 방식이라 토큰 갱신 루프는 없다. `live`

## 6. 네트워크 요건

- **고정 IP 필요.** 키 발급 화면에서 IP를 함께 입력한다. `live` / `3rd`
- 서버 이전 시 IP 재등록이 선행돼야 한다.

## 7. 권한·스코프

발급 단위가 판매자 계정 전체다. 별도 scope 선택 화면은 확인되지 않았다. `unknown`

## 8. 역할 분담

| 주체 | 할 일 |
| --- | --- |
| `[USER]` | Wing 로그인, 사업자 인증 확인, 키 발급 화면 조작, IP 입력 |
| `[AI]` | HMAC 서명 구현, 어댑터·fake 테스트, 발급 후 probe |
| `[3RD]` | (판매자 계정이 고객사 소유면) 고객사 담당자의 발급·IP 등록 |

## 9. 첫 호출 검증

발주서 목록 조회를 최근 짧은 기간으로 read-only 호출해 200과 건수를 확인한다.
401/403이면 §3의 24시간 지연과 §6의 IP 등록을 먼저 의심한다.

## 10. 함정

- 관리자(Wing) 화면 숫자는 **최근 14일 현재 상태** 기준이다. ERP가 DB 누적을 세면
  영구히 어긋난다. `live`
- 생성시각 watermark 증분만으로는 과거 주문의 상태 전이를 놓친다.
  `ACCEPT / INSTRUCT / DEPARTURE / DELIVERING / FINAL_DELIVERY`를 상태별로 재조회한다. `live`
- 취소·반품 주문은 현재 목록에서 **사라진다**. 부재만으로 종결하지 말고 단건 API의
  명시적 응답으로만 확정한다. `live`
- 발주확인(`ACCEPT → INSTRUCT`)은 ERP 로컬 상태 변경이 아니라 채널 write다. `live`
- 묶음배송번호 배치 상한 50. `live`
