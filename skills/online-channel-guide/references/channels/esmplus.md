# ESM Plus (지마켓 · 옥션) — 온보딩 카드

**어댑터 1개로 2채널(지마켓·옥션)을 커버**한다. 사이트 구분은 파라미터로 한다.

| 항목 | 값 |
| --- | --- |
| 내부코드 | `esmplus` (사이트 구분: 옥션 `A` / 지마켓 `G`) |
| 온보딩 등급 | **`REVIEW`** — 이메일 심사, 거절·부분승인 가능 |
| 확인일 | 2026-07-31 |
| 출처 | ESM Trading API `etapi.gmarket.com`, 연동 솔루션사 가이드 |

## 1. 선행조건

- **지마켓·옥션 양쪽 판매회원** 가입. `3rd`
- **ESM+ 로그인으로 마스터 ID 생성**, 판매아이디(옥션·지마켓)를 마스터에 **연동 + 판매승인 완료**. `docs`
- ⚠️ 판매아이디에 **상품판매권한이 없으면** 채널 확대 전에 먼저 해소해야 한다(별건 이슈로 관리). `live`
- 셀링툴사 명의로 신청하려면 회사 사업자정보로 양 사이트 판매자 가입이 별도로 필요하다. `3rd`

## 2. 신청 경로

⚠️ **신청 페이지가 없다. 이메일 심사다.**
현재 공식 안내에 적힌 Trading API 신청 채널로 Community 가입/사용 신청. 주소는 신청 시점의 공식 문서에서 다시 확인한다.
계약서·IP 등록 절차는 없다. `docs` / `live`

## 3. 심사·리드타임 — 이 채널의 핵심 리스크

- 승인은 **"내부 지원 리소스 한도 내"**에서 이뤄지고, **내부 사정에 따라 거절될 수 있다**고
  공식 안내에 명시돼 있다. `docs`
- **리드타임 불확실.** 확정 SLA 없음. 착수 첫날 신청하고 그동안 다른 작업을 진행한다.
- 신청 시 제출/기재하는 것: 신청 명의(판매자 본인 vs 셀링툴사), **최근 매출 실적**,
  개발 기간, 신청 API 범위(주문|배송·클레임·정산·상품·CS·스타배송·서비스). `live`
- ⚠️ **부분 승인 가능성**이 있다. 전 범위를 신청해도 일부만 나올 수 있으므로,
  주문|배송만으로도 핵심 루프가 도는 설계를 우선한다. `live`

## 4. 발급 결과물

⚠️ **Secret(Access) Key를 승인 시 이메일로 수령한다. 셀프서비스 발급 화면이 없다.** `docs`
호출에는 마스터 ID와 판매자 ID들도 함께 필요하다.

## 5. 키 수명·회전

- **토큰 발급 API가 없다.** secret key로 **매 호출 JWT를 직접 서명**한다(HS256). `docs`
- 토큰 유효기간이 문서에 명시되지 않아 **호출마다 생성**이 안전하다. `docs`

```text
Header  alg=HS256, typ=JWT, kid=<ESM+ 마스터 ID>
Payload iss=<클라이언트 도메인 문자열, 자유 기재>
        sub="sell"            (고정)
        aud="sa.esmplus.com"  (고정)
        iat=<발행 timestamp>  (선택)
        ssi=<사이트ID:판매자ID …>   예) 옥션 A:xxx, 지마켓 G:xxx
전송    Authorization: Bearer {token}
```

## 6. 네트워크 요건

**IP 등록 절차 없음.** `docs`

## 7. 권한·스코프

**API 카테고리 단위**로 승인된다(주문|배송, 클레임, 정산, 상품, CS, 스타배송, 서비스).
범위를 넓히려면 추가 신청이 필요하다. `docs`

## 8. 역할 분담

| 주체 | 할 일 |
| --- | --- |
| `[USER]` | ESM+ 마스터 ID·판매아이디 연동 확인, 신청 메일 발송, 매출·개발기간 자료 준비 |
| `[AI]` | JWT 서명 구현, 사이트별 2회 호출 어댑터, fake 테스트, 승인 후 probe |
| `[3RD]` | **ESM 심사역의 승인 (통제 불가·리드타임 불확실)** |

## 9. 첫 호출 검증

`POST https://sa2.esmplus.com/shipping/v1/Order/RequestOrders`를 짧은 창으로 read.
`siteType`을 옥션·지마켓 각각 1회씩 확인한다. 공통 응답 `{ResultCode: 0, Message, Data}`.

## 10. 함정

- ⚠️ **`siteType`: 1=옥션, 2=지마켓 → 사이트별로 2회 호출**해야 한다. 한 번으로 끝나지 않는다. `docs`
- ⚠️ **rate limit: 날짜범위 주문조회 5초당 1회**(주문번호 직접 조회는 무제한).
  옥션+지마켓 각각이므로 백오프 설계에 반영한다. `docs`
- ⚠️ **조회기간 상한이 사이트마다 다르다: 지마켓 31일 / 옥션 180일.** 초기 백필 때
  지마켓만 31일 슬라이싱이 필요하다. `docs`
- 무통장 입금대기는 `PreRequestOrders`에만 나온다. 입금 완료 시 일반 주문조회에 신규 등장한다. `docs`
- ⚠️ **풀필먼트(스타배송) 주문은 주문확인·발송처리 write가 불가**하다(센터 몫).
  수집은 되므로 **주문유형 플래그를 어댑터에서 반드시 보존**하고 write 대상에서 제외한다. `docs`
- 지마켓은 결제 후 약 5분간 전화번호가 null일 수 있다. 구매자 ID는 앞 3자리만 노출. `docs`
- 발송처리는 `ShippingDate`가 호출 2일 이내여야 하고 택배사 코드·송장번호 유효성 검사가 있다. `docs`
- 주문조회 페이징 스펙 **미확인** — 구현 전 원문 재확인. `unknown`

## 11. 폴백

옥션·지마켓 신규주문 엑셀(양 사이트 동일 스키마)의 수동 인제스트.
승인이 지연·거절돼도 이 경로로 업무를 돌릴 수 있으므로 **엑셀 스키마를 먼저 확보**해 둔다.
