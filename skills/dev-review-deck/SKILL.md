# Dev review deck

**목표: 사용자가 폰에서 1~2분 안에 무엇이 바뀌었고 실제로 어디까지 확인됐는지 알게 한다.**
Claude와 Codex가 동일하게 사용한다. 설치된 Playwright 도구나 프로젝트의 Playwright를 재사용하고, 전용 앱·패키지·플러그인을 만들지 않는다.

## 1. 범위 고정 — 이미 아는 것은 묻지 않는다

- 현재 대화, 변경 diff, PR, HANDOFF, 배포 검증 기록에서 완료 기능과 실제 대상 URL을 찾는다. 프로젝트 규칙이 `project-wiki-context`를 요구하면 적용하되, 같은 작업에서 읽은 유효한 맥락은 재사용한다.
- 요청한 환경만 연다. 로컬·개발·운영 중 환경 이름, URL, 확인 시각을 기록한다. 둘 이상 비교 요청이면 환경별 증거를 각각 수집한다. 로컬 화면을 운영 결과로 표시하지 않는다.
- 대상이 불분명할 때만 **프로젝트/URL과 확인할 기능**을 한 번에 짧게 묻는다. 파일·화면만 보고 배포 여부를 추측하지 않는다.
- 기본 범위는 변경된 핵심 흐름 **3~6장**. 화면 하나면 1장으로 끝내도 된다. 전체 메뉴 순회·전체 회귀 테스트·새로운 기획·별도 발표 표지는 추가하지 않는다.
- 이 스킬 호출은 앱 수정·새 배포·운영 데이터 변경·공개 업로드 승인이 아니다. 기존 세션의 구체적인 승인은 재사용한다.

## 2. 캡처 — 실제 사용 흐름과 근거

현재 환경·URL·commit·변경 범위에 맞고 캡처 시각과 관찰 근거가 남은 기존 Playwright 화면은 재사용한다. 오래됐거나 근거가 빠진 화면만 다시 확인한다. screenshot만 있으면 화면 표시 이상의 동작 검증 근거로 확대하지 않는다.

1. **기존 Playwright MCP/browser session → 프로젝트 Playwright 테스트·스크립트** 순으로 사용 가능한 실행 수단을 찾는다. 이미 있으면 재설치하지 않는다. 없으면 프로젝트 의존성을 바꾸기 전에 격리 임시 도구 환경을 사용한다. 브라우저는 필요한 Chromium 하나만 준비한다.
2. 프로젝트가 제공한 테스트 계정·기존 인증 세션·storage state를 재사용한다. 고객 프로젝트 자격증명은 고객 소유의 접근 가능한 출처만 쓴다. 인증이 막히면 해당 장을 `미확인 — 로그인 필요`로 남기고 가능한 나머지를 계속한다. 로그인 화면을 기능 성공 캡처로 쓰지 않는다.
3. **보는 폰 크기와 검사할 앱 크기를 구분한다.** 모바일 기능은 약 `390×844`, 데스크톱 전용 ERP는 약 `1440×900`에서 확인한다. ERP를 억지로 모바일 레이아웃으로 바꾸지 않는다. 필요한 부분만 잘라 추가하면 폰에서 읽기 쉽다.
4. 화면 진입 후 기능을 대표하는 locator/텍스트/응답으로 준비 완료를 기다린다. 고정 sleep이나 끝나지 않는 `networkidle`에 의존하지 않는다. 탭·검색·상세 열기 등 허용된 흐름을 실행하고 **보이는 결과를 assertion**한 후 캡처한다.
5. `page.screenshot` / `locator.screenshot` 또는 도구의 동등 기능을 쓴다. 기본은 viewport 또는 핵심 영역, `scale: 'css'`, `animations: 'disabled'`. 파일 형식을 지원하면 JPEG quality 약 75로 저장한다. 세로로 긴 full-page PNG·영상·trace는 요청이나 실패 조사에 필요한 경우에만 만든다.
6. 개인정보·고객명·연락처·토큰이 보이면 캡처 **전에** 해당 locator를 mask한다. 마스킹이 확인할 기능 자체를 가리면 가능한 비식별 테스트 데이터로 바꾸거나 그 한계를 명시한다. 인증 state, 쿠키, `.env`, 응답 원문은 덱 디렉토리에 넣지 않는다.
7. 캡처 옆에 실제 관찰 결과를 남긴다. 예: `검색어 입력 → 결과 2건 표시 확인`. 새 오류가 보이면 실패를 그대로 기록한다. 운영의 저장·삭제·발송·결제 등 변경 동작은 기존 명시 승인 범위에서만 실행한다.

**증거 규칙:** `확인`은 assertion/직접 관찰이 있는 항목, `문제 발견`은 재현된 항목, `미확인`은 실행하지 못한 항목이다. 화면이 열렸다는 이유만으로 저장·권한·정산·전체 기능을 통과로 표시하지 않는다. 기존 build/lint/test 기록은 실행 환경·시각·commit이 현재 대상과 맞을 때만 인용한다. 캡처 목적만으로 이미 통과한 전체 검증을 다시 돌리지 않는다.

## 3. HTML 구성 — 고정 마스터에 증거만 채운다

`design-workflow`로 최소 모드 판단은 한다. 프로젝트/이전 결과의 **승인된 모바일 덱 마스터**가 있으면 `small-feature`로 레이아웃·스타일을 그대로 재사용하고 캡처와 설명만 채운다. 정본이 없거나 새 디자인을 요청하면 `new`/`refactor`의 해당 게이트를 따른다. 이 스킬은 전역 디자인 승인 규칙을 면제하지 않으며, 첫 승인 뒤에는 같은 마스터에 대한 디자인 인터뷰·3시안을 반복하지 않는다.

새 마스터를 정할 때의 기능적 수용 기준:

- 기본 읽기 흐름은 **세로 스크롤**, 기능마다 `변경점 한 줄 → 실제 화면 → 확인 결과 한 줄`. 이미 선택한 다른 읽기 방식이 있으면 그것을 우선한다.
- 맨 위에 프로젝트·환경·확인 시각, 핵심 변경을 짧게 표시한다. 마지막에 문제/미확인 항목이 있을 때만 붙인다. 허구의 개선율·테스트 숫자를 만들지 않는다.
- 덱 자체는 폭 360~430px 폰에서 가로 넘침 없이 읽힌다. 본문은 16px 이상, 시스템 폰트, 충분한 명암 대비. 캡처 원본은 탭해서 확대할 수 있게 직접 이미지 링크를 둔다. 핀치 줌을 막지 않는다.
- **정적 `index.html` + 상대경로 이미지**만으로 작동한다. CSS는 inline, 기본 JS는 0. 외부 CDN·웹폰트·아이콘 패키지·React·슬라이드 라이브러리·차트·애니메이션·새 빌드 환경은 필요 없다.
- 첫 화면 이미지는 바로 로드하고 나머지는 `loading="lazy" decoding="async"`, 이미지 크기를 지정한다. `max-width:100%; height:auto`로 비율을 보존한다. 이미지를 base64로 HTML에 합치지 않는다.
- 목표는 HTML 50KB 이하, 이미지 포함 **약 3MB 이하**. 실제 파일 크기를 잰다. 초과하면 중복 컷 제거 → 영역 캡처 → 지원되는 JPEG quality 조정 순으로 줄인다. 작은 글자 가독성을 위해 초과가 필요하면 실제 용량을 알린다.
- 텍스트와 속성은 HTML escape한다. 원본 앱 링크가 필요하면 공개 가능한 origin/path만 쓰고 사용자정보·토큰 query/fragment는 제외한다. 로그·인증 파일·내부 응답을 embed하지 않는다.

프로젝트의 기존 산출물 위치를 우선한다. 없으면 task 전용 임시 디렉토리에 `public/index.html`과 `public/images/`를 둔다. 인증·캡처 스크립트·검증 메모는 **public 바깥**에 둔다. 요청 없이 repo 레이아웃·의존성·전역 규칙을 추가하지 않는다.

## 4. 폰 접속과 확인

1. **public 디렉토리만** 로컬 HTTP 서버로 제공한다. repo 루트나 인증 파일이 있는 폴더를 서빙하지 않는다. 예: `python3 -m http.server <빈 포트> --bind 0.0.0.0 --directory <public-dir>`. 시작한 서버의 PID와 경로를 기록하고 에이전트가 백그라운드 생명주기를 관리한다.
2. 실행 중인 머신의 Tailscale IPv4를 조회한다. CLI는 `command -v tailscale`, 없으면 macOS 앱의 `/Applications/Tailscale.app/Contents/MacOS/Tailscale`을 확인하고 `ip -4`를 실행한다. 사용 불가하면 LAN IP 또는 `<hostname>.local`로 폴백한다. IP를 스킬에 하드코딩하지 않는다.
3. URL 경로를 인코딩하고 실제 `http://<주소>:<포트>/index.html`이 HTTP 200인지 확인한다. 이 체크는 서버 측 접근 증거이며 **사용자의 폰 접속 성공**을 뜻하지 않는다. 폰에는 같은 Tailscale 네트워크가 필요하고 LAN 폴백은 같은 LAN이 필요함을 짧게 덧붙인다.
4. Playwright로 **생성한 덱**을 390px 폰 viewport에서 연다. 전 장을 스크롤해 lazy 이미지 로드를 확인하고, 깨진 이미지·가로 overflow·console 오류·확대 링크·글자 잘림을 확인한다. 문제는 덱 범위에서 고친다. 검증 스크린샷은 public 밖에 둔다.
5. 별도 종료 지시가 없으면 대화를 기다리는 리뷰 동안 서버를 유지하고, 리뷰 종료 또는 세션 종료 때 이번 작업이 띄운 서버·브라우저를 정리한다. 다음 사용자 응답에서 리뷰가 계속되면 먼저 서버 생존/200을 확인한다. 즉시 끄고 죽은 URL을 최종 답변으로 주지 않는다. 세션 종료 시 정리를 지원하지 않는 실행 환경이면 수명 제한을 둔 프로세스로 띄우고 만료 시각을 알린다.
6. 이미 승인된 프로젝트 배포 경로로 이 덱이 배포됐다면 검증된 배포 URL을 정식 링크로 쓴다. 폰 접근이 안 된다는 이유로 공개 터널·새 호스팅·앱 배포를 자동 생성하지 않는다.

## 완료 응답

**덱 URL을 첫 줄**에 주고 `환경 · N장 · 실제 용량 · 확인 결과`를 짧게 적는다. 문제가 있으면 한 줄로 알린다. 로컬 서버 링크라면 접근 조건·서버 수명도 표시한다. 사용자가 원하지 않은 긴 작업 보고·퀴즈·이중 승인 질문을 붙이지 않는다.

호출 예: `이번에 개발서버 나간 주문 검색 기능 dev-review-deck으로 보여줘. 폰에서 볼 거야.`
